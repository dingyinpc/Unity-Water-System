## A.  Shader / HLSL

### ★A-1 `SV_Position` 在片元阶段是**像素坐标**，不是裁剪空间

- **现象**：水面永远发奶白、不透。屏幕空间折射采到的画面纹丝不动，深度项看起来完全失效；换任何水面颜色参数都只是"换个颜色的奶白"。持续了多个开发日。
- **真因**：结构体里用 `float4 position : SV_POSITION` 同时当"光栅化位置"和"裁剪空间坐标"用。到了片元函数，`SV_Position.xy` 已经是**像素坐标**（0..1920 / 0..1080），`/w` 得到的 `screenUV` 是个巨大的数，折射 UV 和 `SampleSceneDepth` 全部取到画面角落的污染值。
- **解法**：结构体里**另带一份裁剪坐标**：
  ```hlsl
  struct WaterVaryings {
      float4 positionCS : SV_POSITION;   // 光栅化用
      float4 clipPos    : TEXCOORD3;     // 屏幕空间采样必须用这个
      ...
  };
  // domain shader:
  o.positionCS = TransformWorldToHClip(gr.pos);
  o.clipPos    = o.positionCS;
  // fragment:
  float4 posCS = IN.clipPos;
  ```
- **教训**：**语义名决定了值的含义**，同一个值在顶点/几何/片元三个阶段不是一回事。屏幕空间效果（折射、深度重建、抓屏）永远要自己把裁剪坐标传下去，别蹭 `SV_Position`。
- **连带影响**：这个 bug 掩盖了下游所有判断——我基于它产出的"深度诊断数据"得出过"深度纹理取不到"的错误结论（见 I-1）。**先确认观测通道可信，再解释观测结果。**

### A-2 噪声梯度声明成 `float` 却按二维用

- **现象**：`invalid subscript 'y'`。
- **真因**：`float du = ...;` 然后写 `du.y`。
- **解法**：`float2 du = 6.0 * f * (1.0 - f);`。同理二维方向向量只有 `.x/.y`，写 `.z` 也报 `invalid subscript`。

### A-3 HLSL 不允许函数内定义函数

- **现象**：`syntax error: unexpected token '('`。
- **解法**：把内层函数提到文件作用域。

### A-4 波浪参数数组不落盘

- **现象**：材质面板里 `_Waves` 永远是零值，几何波完全不推动；但重启后"看起来有波"（其实是细节法线在动）。
- **真因**：该编译配置把 `_Waves` 当**标量 Vector 属性**处理，`GetVectorArray` 返回长度 1，`SetVectorArray` 只对第 0 条生效且不序列化。
- **解法**：波浪改成 **shader 内置固定波**（A/ω/Q 硬编码）+ `_WaveAmpScale` 一个幅度旋钮。
- **教训**：Unity 材质数组的序列化行为跟 shader 里的声明方式强相关。**验证方式是"重启后还在不在"**，不是"这一帧看着对"。

### A-5 细分因子按固定倍率 → 三角形爆炸

- **现象**：FPS 崩到 1.7，水体画不出来。
- **真因**：`_MaxTess=12` 套在 40m 池塘、基边 0.42m 上 → 细分到 3.5cm 微型三角 → 百万级面。
- **解法**：按**目标世界尺寸**自适应：`factor ≈ 基边长 / _TessTargetSize`。任何网格分辨率都收敛到同一三角形密度。
- **教训**：曲面细分预算要按"屏幕上多大"定，不是按"细分几次"定。

## B.  URP 与渲染配置

### ★B-1 `VolumeProfile.Add<T>()` 不落盘，后处理整条静默空操作

- **现象**：ACES、postExposure、saturation 全部调了，画面**一个像素都没变**。反复怀疑"ACES 把画面压暗了"并据此做了一堆错误推理。
- **真因**：`profile.Add<T>()` 只创建内存对象，不调 `AssetDatabase.AddObjectToAsset()` 就永远不写进 `.asset`。结果 profile 里是 `components: [fileID: 0, fileID: 0]` 两个空槽。
- **解法**：
  ```csharp
  prof.components.RemoveAll(c => c == null);          // 清掉历史空槽
  ton = prof.Add<Tonemapping>();
  AssetDatabase.AddObjectToAsset(ton, prof);         // ← 关键
  ```
- **教训**：**"设置没生效"和"设置根本没被保存"是两回事**。验证方式是打开 `.asset` 看 `m_Component` 里有没有真实 fileID，或者做一次极端值测试（把 postExposure 设 -4，画面没变 = 通道不通）。

### ★B-2 Scene 视图不吃 Volume，只有 Play 的 Game 视图吃

- **现象**：在 Scene 视图里截图，改后处理参数数值不动。
- **验证**：把 `postExposure` 设成 `-4`，Scene 视图**零变化**；即使给 Scene 相机手动挂 `UniversalAdditionalCameraData` 并 `renderPostProcessing = true` 也没用。
- **解法**：**所有观感判断必须在 Play 模式的 Game 视图里做**（菜单43）。Scene 视图只能看构图和几何。
- **教训**：先验证观测通道，再验证被测量。这条和 A-1 是同一个错误的两种表现。

### B-3 URP 14 没有 `Fog` 的 VolumeComponent

- **现象**：写 `UnityEngine.Rendering.Universal.Fog` 编译报 CS0234。
- **真因**：URP 14 的 `Runtime/Overrides/` 里确实没有 Fog（只有 Tonemapping / ColorAdjustments 等）。
- **解法**：雾走 `RenderSettings.fog / fogMode / fogColor / fogDensity`。
- **教训**：**别凭记忆写 API**，先列一下目录确认组件存在。

### B-4 折射/深度需要 Opaque + Depth Texture

- **要求**：URP Asset 里 **Opaque Texture**（采屏幕空间背景）和 **Depth Texture**（算水深）都必须开。少一个就是水面纯贴图或奶白。

### B-5 阴影距离会把远景道具收进来

- **现象**：远岸草坡上出现一道道长条黑影；沙滩上横一条硬阴带。
- **真因**：`m_ShadowDistance = 140` + 太阳仰角 30°，于是 r30~50 的树、整圈远岸绿墙全在阴影投射范围内。
- **解法**：背景类物体（草坡、远树）统一 `shadowCastingMode = Off`。它们只需要剪影，不需要自投影。

### B-6 共面 z-fighting

- **现象**：陡视角下草地"吃掉"水面，Game 视图一片绿灰，水面取色被污染。
- **真因**：地面顶面 y=0 与水面圆盘 y=0 **完全共面**。
- **解法**：水面上浮 2cm（y=0.02），水面上的物件（荷叶）相对高度照旧。

## C.  光照与颜色校准

### ★C-1 ACES 的趾部会吞掉整个中间调

- **现象**：岩石阴影面实测 `(30,41,53)`，参考帧是 `(88,122,151)` —— 线性亮度差约 **8 倍**。
- **真因**：`postExposure 0.55` 太低，中间调整个落在 ACES 曲线的趾部里被压平。此时**无论怎么调反照率都拉不上来**（调高只会让亮的过曝、暗的还是死）。
- **解法**：先把 `postExposure` 抬到 1.15，**再**调反照率。
- **教训**：调色的顺序必须是 **曝光 → 光源 → 反照率**。反过来做会得到"参数怎么调都没用"的假象。

### ★C-2 "受光 ≈ 阴影"是天光填充的判据

- **现象**：岩石近黑，第一反应是"反照率太低"，改了三轮没用。
- **真因**：参考帧实测**受光岩 `(103,130,154)` ≈ 阴影岩 `(88,122,151)`**，差不到 1.2 倍 —— 说明那是个几乎平涂、天光主导的场景，而我们直射光占比过高、环境光过弱。
- **解法**：ambient sky 从 `0.22` 提到 `0.50,0.58,0.68`。
- **教训**：**先量参考帧的"明暗差比"，再决定是调光还是调材质。** 只看单点亮度会得出完全相反的结论。

### C-3 太阳仰角决定所有朝上面的亮度

- **现象**：岩石顶、树冠、沙面**集体**发黑。
- **真因**：太阳被压到仰角 14°，朝上面的 `N·L = sin14° = 0.24`。
- **解法**：仰角回到 30°。
- **教训**：**"很多物体同时暗"通常是光源问题，不是逐个物体的材质问题。** 找共因，别一个个调。

### ★C-4 同一个物理量被两个菜单各写一遍

- **现象**：明明改了菜单48 的太阳仰角，跑完整链还是暗的。反复怀疑"提 ambient 没用"。
- **真因**：菜单54（低机位）为了保碎闪**又写了一次** `Euler(14,208)`，而 54 在 48 **之后**跑 → 48 的值被静默覆盖。
- **解法**：**删掉菜单54 的赋值**，让菜单48 成为唯一来源；改由相机俯角去适配太阳仰角。
- **同类第二次**：`_FresnelPow` 由菜单40 设为 6，40 在 48 之前跑 → 必须在 48 里显式覆盖一行。
- **同类第三次**：菜单48 内部 `_SkyReflect` 有两行赋值（0.55 与 0.75），后者静默胜出。
- **教训**：**"几何耦合"不等于"要重复赋值"。** 全局参数要有唯一写入点；调试"改了没反应"时，第一件事是 **grep 这个属性名被写了几次**。

### C-5 脚本 `SetColor` 是线性空间

- **现象**：按 sRGB 目测取的颜色写进去，渲出来偏艳偏暗。
- **解法**：`Material.SetColor` / `.mat` 里的值都是**线性**；从截图取的 sRGB 要先转线性（`c ≤ 0.04045 ? c/12.92 : ((c+0.055)/1.055)^2.4`）。
- **教训**：所有最终值都应"经 Play 真实 Game 视图（含 ACES）取样校准"，不要靠换算直觉。

### C-6 大气透视 ≠ 变暗

- **现象**：远山调暗之后变成"黑三角"，逆光剪影生硬。
- **真因**：大气透视的正确方向是 **提亮 + 压饱和 + 偏蓝**，不是压暗。
- **解法**：`Hill_Distant → 0.34,0.42,0.46`（蓝 > 绿）。
- **配套判据**：**远景偏绿 = 反照率 G 抬太高而 B 没跟上。**

### C-7 ACES 的色相限制会把饱和色压成暗色

- **现象**：荷花给了 `(0.90,0.26,0.50)` 的"粉"，渲出来是**砖红**。
- **真因**：高饱和洋红/红色被 ACES 色相限制强烈压缩。
- **解法**：用**浅粉** `(0.92,0.56,0.66)` —— 提亮 + 降饱和才保得住。
- **教训**：想要某个鲜艳颜色，给它的输入要比直觉**更亮、更不饱和**。

### C-8 沙地"不像"往往是缺蓝，不是太亮

- **现象**：沙滩读成橙褐。第一反应"太亮了"，压暗之后变成脏灰。
- **真因**：蓝通道比参考低 27。
- **解法**：**补蓝**，不是降明度。
- **反向坑**：补过头（近中性 `0.46,0.45,0.45`）会让沙滩在蓝天光下洗成蓝白 —— 暖调要保留。

## D.  水面观感

> 这一类是本项目最贵的部分。水面是"一个 shader + 十几个参数"的耦合系统，**单点调参会互相掩盖**。

### ★D-1 高光无界累加 → 整块死白光斑

- **现象**：水面突然出现大片突兀的白色光斑。
- **真因**：两条叠加 ——
  ① `col += _SunColor * spec` 是**无界累加**，把本来就亮的水色顶过 1.0，被 ACES 削平成一片死白；
  ② 细节法线只有低频八度，**一大片面元朝向几乎相同** → 一起亮。
- **解法**：
  ```hlsl
  float spec = saturate(pow(saturate(dot(N,H)), _SpecPower) * _SpecStrength);
  col = lerp(col, _SunColor.rgb, spec);          // 有界：上限就是 _SunColor
  ```
  并加第三层高频八度把碎闪打碎成点。
- **教训**：**累加式高光必须设上界。** `lerp` 到光源色比 `+=` 安全得多。

### ★D-2 泡沫/深度带用"视深"算，低机位下直接消失

- **现象**：岩石水线处完全没有参考帧那种白沫领圈。
- **真因**：`gap = sceneDepth - waterDepth` 是**沿视线的距离**。低机位视线接近水平时，**1m 垂直水深被换算成 ~4m 视深**，泡沫带宽被压到约 17cm → 看不见。
- **解法**：先换算回垂直水深，带宽才与观察角度无关：
  ```hlsl
  float vd = gap * max(V.y, 0.12);
  float shoreFoam = saturate((1.0 - vd * 1.7) * (1.0 - fres) * 0.75);
  ```
- **教训**：**任何"按水深"的效果都必须显式区分垂直水深和视深。** 同一个 bug 还让吸收系数把整池判成深水（D-3）。

### ★D-3 `_Absorb` 作用在视深上 → 浅池全池"深水色"

- **现象**：水"不透"，而且**近岸比塘心还暗**（与参考帧完全相反）。
- **真因**：池子最深只有 1.30m，`_Absorb 1.9` 配视深使 `depthMix = 1-e^{-gap·1.9}` 全池 ≈ **0.92** → 浅滩也被当成深水。
- **解法**：`_Absorb → 0.85`（1.3m 处 depthMix ≈ 0.67）。
- **教训**：**吸收系数要按"这个池子实际多深"标定**，没有通用值。换个场景尺寸就得重标。

### ★D-4 碎闪"点不亮"是**角度**问题，不是强度问题

- **现象**：参考帧亮带 `med(208,218,201)` 近白，我们 `(69,149,171)`。
- **走过的弯路**：按直觉连抬 `_SpecStrength 1.1→1.7→2.0`、`_SunStrength 1.4→2.6→3.4`，实测只爬到 `(95,177,175)`，**几乎无效**。
- **真因**：两个**角速度**参数把高光限制在极小区域：
  - `_SunGloss 700` → `pow(cosδ, n)` 半高宽约 `1.3/n` 弧度 ≈ **±1.8°**，在 52° 视场里只占 4% 画面高度 → 太阳高光是**一条线**，不是**一片**；
  - `_FresnelPow 6` → 水面俯角 10° 时 `fres` 才 **0.33**，必须贴着地平线才趋近 1 → **画面绝大部分水面根本没在"照镜子"**，`col += skyCol*fres*_SkyReflect` 这条路径基本不成立。
- **解法**：`_SunGloss → 90`、`_FresnelPow → 4`、`_SkyReflect → 1.0`；并因覆盖面积涨约 8 倍把 `_SunStrength` **降回** 2.2，否则整幅洗白。
- **教训**：**"高光不够亮"先算它在画面那个几何条件下能取到多少**，再谈强度。再大的强度乘在 4% 覆盖率上还是一条线。

### D-5 "波瓣宽 = 光斑大"只在法线低频时成立

- **背景**：D-1 之后我们学到"波瓣要窄"，于是把 `_SpecPower` 拉到 900、`_SunGloss` 拉到 1500。
- **反例**：D-4 需要放宽波瓣，但没有重现死白。
- **真因**：细节法线已经是**三 octave、`_DetailScale 7.6`**，面元足够小足够密，放宽波瓣只会让点变多变亮。
- **教训**：**"波瓣宽度"必须和"法线频率"成对考虑**，不能单独当结论记。上一轮的"正确参数"可能是这一轮的瓶颈。

### D-6 透彻感 = 透明权重 + 折射位移上限

- **现象**：放大看"发糊、像蒙了层色膜"。
- **真因**：看穿湖底只有两条路——折射项（因 depthMix 饱和权重≈0）和未位移的 `sceneCol`（被 `_Opacity 0.95` 压到只剩 5%）；而 `_MaxUVOffset 0.12`（屏幕比例，906px 下 ≈108px）把任何折射都抹成一团糊。
- **解法**：`_Opacity → 0.76`、`_MaxUVOffset → 0.025`、`_RefractStrength → 0.3`。
- **教训**：折射位移上限是个**极敏感**参数，0.1 和 0.025 是"糊"和"透"的分界。

### D-7 浅滩发灰 = 池底色相问题，不是水面色问题

- **现象**：近岸浅滩带是灰的，参考帧是淡薄荷绿。
- **走过的弯路**：① 以为是盆缘破水 → 改 `Rim`；② 以为是台地硬边 → 砍抬升量；③ 以为是过曝 → 压沙色。**全部无效。**
- **定位方法**：在 Play 里 `setProperty active=false` **逐个隐藏** `Ground`/`PondBasin`/`BasinStep_*`，画面里那条带**完全不动** → 它不是独立物体；改 `_ShallowColor` 时它**跟着变** → 归水管。
- **真因**：折射层把池底大量混进水色，`Ground_Lake` 是暖褐 → 混出来发灰。
- **解法**：池底与水下沙材质改成**绿反超红**的黄绿沙。
- **教训**：**"排除法 + 单变量响应"比"猜测 + 修改"快得多。** 而且——对照参考帧后发现**构图A 底部本来就有这条浅滩带**，差点为一个不存在的问题重构盆底。

### D-8 交互涟漪的白圈

- **现象**：水面莫名冒出白色大圈。
- **真因**：演示模式每 0.45s 随机砸一次涟漪，shader 里交互泡沫以白色 `_FoamColor` 强叠。
- **解法**：demoInterval 0.45→4s、强度 0.5-1→0.18-0.42、`_InteractionAmp 0.35→0.22`、`_InteractionFoam 0.9→0.45`、尾叠乘数 0.4→0.12。

### D-9 水面"棋盘格"不是细分接缝

- **现象**：水面出现规则方格状接缝，第一反应是曲面细分的 patch 边界。
- **真因**：噪声函数**梯度不连续**（`frac`/`floor` 边界上导数跳变）。
- **解法**：改用值噪声的光滑插值（smoothstep 五次多项式）而非线性插值。
- **教训**：**"看起来像网格"不一定是网格拓扑问题**，先查函数连续性。

## E.  程序化几何与地形

### ★E-1 绕序反了 → 整片沙滩"消失"

- **现象**：俯视机位一抬高，水外面全是草地而不是沙。第一反应是"沙的颜色不对"。
- **真因**：探针实测 `ShoreSandRing avgNrmY = -1.000`、`PondFloorShore avgNrmY = -1.000`，而 `Sand_Shore.mat` 是 `_Cull: 2`（背面剔除）→ **沙滩根本没被画出来**，露出的是下面 y=-0.5 的草地。
- **解法**：菜单46 统一把地面网格绕序翻正 + 显式朝上法线（`avgNrmY → +0.977`）。
- **教训**：**"看不到"和"颜色错"是完全不同的故障。** 低机位之所以"看着有沙"，是掠射角下前向面恰好可见 + 看到的其实是池底。**先确认它被画了，再谈画得好不好。**

### ★E-2 同心台地 → "靶心"/体育场

- **现象**：为了做凹陷感加了三圈同心台地，结果看着像体育场或波纹槽，完全不像挖出来的沙坑。
- **真因**：等参数 t 生成的同心环**过于规则**。
- **解法**：`WobA(th, seed)` —— 三组低频正弦（2θ/5θ/9θ，相位取自稳定哈希 `Hash11`）合成**平滑**角向扰动，**同时作用于盆底等深线和台地边界**，让两者沿同一套轮廓走、不错位穿帮。
- **教训**：**程序化地形要"不规则"，但必须用低频平滑函数扰动**；直接叠逐顶点随机噪声会变成麻点。

### ★E-3 高频起伏 + 平面着色 = moiré 条纹

- **现象**：远岸草坡坡面出现一道道同心明暗条纹。
- **真因**：上缘用了 `11θ + 23θ` 高频正弦，在平面着色 + 256 段的网格上**被打拍成 moiré**。
- **解法**：降到 `3θ + 7θ` 低次谐波。
- **教训**：**着色频率决定了几何细节的上限。** 平面着色下任何高于网格采样率一半的细节都会折叠成假条纹。

### E-4 重合顶点 → 退化三角 → 零法线

- **现象**：`RecalculateNormals()` 之后一半顶点法线是零，渲染出淡青横带和斜向尖刺。
- **真因**：网格构造时同一位置塞了多个顶点（内壁/顶/外壁共用坐标），产生退化三角；`RecalculateNormals` 对退化面得到零法线（实测 294/582 为零）。
- **解法**：**显式给法线**，或保证三角形非退化。
- **配套**：非索引化（每三角形独立顶点）+ `RecalculateNormals` = 逐面法线 = 想要的低多边形平面着色。

### E-5 台地是"深度突变"，水一透就露馅

- **现象**：水面透明度提上来后，近岸出现笔直的灰白分界线。
- **真因**：每圈台地的外缘都是一次**深度不连续**，透明水面会把它直接画出来。
- **解法**：抬升量 `0.055+0.075t → 0.010+0.016t`（约 1/5），凹陷改由锥形盆底单独承担。
- **教训**：**几何细节的可见性取决于覆盖它的介质透明度。** 水面变透 = 一次性暴露所有水下几何的硬边。

### E-6 盆底边缘与水面共面 → 破水而出

- **现象**：近岸糊出一道"水泥台阶"。
- **真因**：盆底 `Rim = +0.02` 正好等于水面高度 y≈0.02 → 完全共面。
- **解法**：`Rim → -0.07`，让盆体外缘**低于水面**。

### E-7 道具贴合：采样网格，不要复制公式

- **现象**：改了盆底剖面之后，探针审计出 **19 件悬空**（7 块深水巨石底面高出新盆底 0.16~0.47m、4 株荷叶落到干滩）。
- **走过的弯路**：想再写一个高度公式来算贴合。
- **真因**：水面/沙环的半径公式**已经在菜单22/24/36/52 各写了一遍并且已经漂移**（例如菜单24 给水面加了 +z 凸出 2m，菜单36 重建时又没有）。再抄一份只会制造下一次不一致。
- **解法**（菜单53）：直接**采样场景里真实存在的地面网格世界顶点**（44297 个）建高度场，取水平容差内最高 y 当地面，按"埋入自身高度 25%"重坐。
- **验证**：幂等 —— 连跑两次第二次报 `moved 0 kept N`，说明收敛而不是反复抖动。
- **教训**：**永远以"画面里实际有什么"为准**，不要维护一份并行的解析模型。

### E-8 散布尺寸要按像素反推

- **现象**：撒了 179 颗卵石，画面上完全看不见，远岸仍然光秃。
- **真因**：scale 0.055~0.175 → 直径 0.12~0.39m，在 20~25m 外只有 **1~3 像素**。
- **解法**：改成 0.16~0.40（直径 0.35~0.9m）。
- **教训**：**程序化散布的尺寸要按"它在画面里占几个像素"反推，不是按米。** 同类错误：荷叶尺寸从"9-14cm"的错单位估算一路改到按 glb 实际尺度反算（见 F-1）。

### E-9 散布密度要按视线方向加权

- **现象**：均匀绕圆撒的道具，画面里看着还是稀。
- **真因**：相机 yaw 9° 意味着视线朝 +z，均匀撒的话密度全花在画面外的近岸和两侧。
- **解法**：额外补 5 簇专门落在 θ≈π/2 那一侧。

### E-10 移动带子节点的物体：不要手算锚点

- **现象**：编译报 `CS0019: Operator '*' cannot be applied to operands of type 'Vector3' and 'Vector3'`；而且手算的公式**漏了父节点的旋转**。
- **解法**（与旋转/缩放都无关的两步写法）：
  ```csharp
  t.localScale = new Vector3(sc, sc, sc);           // 先改缩放
  t.position  += (target - keep.position);           // keep.position 每次现算世界矩阵
  ```
- **教训**：**子节点的 `position` getter 实时反映父矩阵**，拿它当锚点天然正确。别去拼 `localPosition * lossyScale`。

## F.  资产 / GLB / 材质

### ★F-1 glb 的单位可能完全不是你以为的

- **现象**：低机位下荷叶像木筏。探针实测 `scale=0.15 → 直径 4.26m`，即该 glb 在 scale=1 时约 **28.4m**。
- **真因**：早期注释写的"9-14cm"是**按错误单位估的**，之后所有尺寸都建立在它上面。
- **解法**：**先量出 glb 在 scale=1 下的真实尺寸，再从目标直径反算 scale**：`sc = 目标直径 / 实测直径`。
- **教训**：**导入外部模型第一件事是量包围盒**，不要信文件名、缩略图或注释里的尺寸。

### ★F-2 glb 内嵌材质不可写，只能整只 Renderer 覆盖

- **现象**：给荷叶/荷花改了材质表里的颜色，没反应。
- **真因**：菜单48 的 albedo 字典只 `LoadAssetAtPath<Material>("Assets/Art/Materials/<名字>.mat")`，**碰不到 glb 内嵌的材质**（gltfast 生成的材质在 `.glb` 资产内部）。
- **解法**（菜单56 `ForceMat()`）：实例化之后遍历 `GetComponentsInChildren<Renderer>(true)`，把 `sharedMaterial` 整个换成自建材质。
- **两条子教训**：
  - **荷花要双面**：`_Cull = 0`。荷叶"一圈黄边"根本不是高度问题，而是**模型背面本就是黄色**、背面剔除让它露了出来。双面 + 正反面同色一并解决。
  - 想按物体类型定向替换时，先**打印 Renderer 名 + 原材质名**再决定映射规则，别猜。（本项目做法：菜单里塞一个 `diag < 6` 的探针输出。）

### F-3 材质是"实例快照"，改资产不生效

- **现象**：菜单里 `SetColor` 改了资产，渲染颜色纹丝不动。
- **真因**：场景对象（尤其 prefab 实例）渲染的是**材质实例快照**而不是资产引用。
- **解法**：菜单23「强制重挂场景全部材质」—— 按 `sharedMaterial.name` 去 `Assets/Art/Materials/` 找同名资产重挂。
- **教训**：**改资产 ≠ 改场景里的引用。** 需要一步显式的 rebind。

### F-4 gltfast 的 GLB 在手动 `cam.Render()` 下不渲染

- **现象**：非 Play 的截图里树/荷叶"消失"，而且连续两次截图**字节级完全相同**。
- **真因**：① gltfast 导入的 GLB prefab 实例在编辑器手动 `cam.Render()`（桥截图机制）下不渲染；② 水面 shader 的 `_Time` 在非 Play 也冻结。
- **解法**：GLB 物体用**场景文件核对**（`Main.unity` 里 `SmallLily_*` 的 m_LocalScale / `Tree_ring_*` 数量），或进 Play 亲验。
- **教训**：**"两次截图一模一样"本身就是个信号** —— 说明时间没走、渲染路径不对。

### F-5 UPM 版本号写错是静默失败

- **现象**：`.glb` 放进 Assets 只有 `.meta`、没有预制体。
- **真因**：gltfast 写了 6.4.1（**不存在**），manifest 解析失败但**不报错**，`packages-lock.json` 不更新。
- **解法**：先查注册表 `GET https://packages.unity.com/<包名>` 看 versions 列表；改完**重启编辑器**强制解析（UPM 文件监听不保证触发）。

### F-6 重建网格资产后 MeshFilter 引用变 null

- **现象**：删旧网格 + `CreateAsset` 重建后，场景里 `Water` 的 MeshFilter 显示 `m_Mesh = null`，水不渲染。
- **真因**：内存里的 `Mesh` 对象无法被序列化进场景。
- **解法**：重建后必须 `AssetDatabase.LoadAssetAtPath<Mesh>(path)` 取**资产引用**再赋给 MeshFilter。
- **配套**：就地覆写已有 Mesh 资产要用 `Clear()` + 逐字段赋值，**不能用 `CopySerialized`**（只复制序列化字段，GPU 顶点/法线缓冲会留空）。

### F-7 `instantiatePrefab` 会重置 localScale

- **现象**：实例化后变成 1×1×1。
- **解法**：显式传 `scale`。

### F-8 原语 Collider 类型不要写死

- **现象**：菜单12 第一版 `GetComponent<MeshCollider>().enabled=false` 拿到 null 抛空引用，`PondWall` 根本没建成，**但菜单按钮仍返回成功**。
- **解法**：改按通用 `GetComponent<Collider>()` 再 `DestroyImmediate`。
- **教训**：**运行后必须用 `findGameObjects` 点名验证实际产物**，不能只看菜单返回。

## G.  Unity 编辑器与 MCP 桥

### ★G-1 `runMenuItem` 永远返回 ✅，即使抛异常或菜单不存在

- **现象**：以为菜单跑成功了，实际什么都没发生。
- **解法**：**唯一可信的通道是往文件写探针**（本项目：`Logs/water_probe.txt`）。每个菜单开头/结尾各写一行，失败写 `FAIL`。
- **配套**：整链重建菜单（57）在**每一步之前**写 `STEP n`，中途炸了能定位。

### ★G-2 `runMenuItem` 会把 Unity 最小化 → 截图永不落盘

- **现象**：菜单43 在探针里写了 `captured`，但 `_gameview.png` 的 mtime 不动。
- **真因**：编辑器一旦最小化就不渲染，`ScreenCapture.CaptureScreenshot` 排队的帧永远不 flush。
- **解法**：**先跑截图菜单，再 `activate_window`** —— 被排队的帧会在恢复前台时补写出来。反过来"先 activate 再截图"没用，因为截图那次调用本身又把它最小化了。
- **判据**：**比对目标 png 的 mtime 有没有前进**。只看"菜单返回 ✅"会把"材质没生效"和"根本没有渲染"混为一谈。

### ★G-3 退出 Play 模式**不一定**回滚场景改动

- **现象**：为了做近景检查，在 Play 里用桥把 `Main Camera` 挪到 `(0,1.6,-5.5)`，**退出 Play 后它仍是这个值**。
- **真因**：桥的 `setProperty` 走了 `Undo.RecordObject` + `SetDirty`。
- **解法**：临时改相机/物体做检查后，**必须读回属性确认**并手动复位，再 `saveScene`。
- **反向坑**：在 Play 里**创建**的物体（菜单55/58 的产物）退出 Play 就没了 —— 要么在编辑模式跑完再进 Play，要么退出后重跑。

### G-4 编辑器没有 Console 回读通道

- **现象**：`Debug.Log` 取不回来。
- **解法**：要拿实况就在菜单里**写到文件**再读。

### G-5 `Editor.log` 的行号和错误都是陈旧的

- **现象**：已经修好的 `receiveShadow` 报错仍显示在 3369/3411 行；grep 出来的 `error CS` 大部分是历史。
- **真因**：`Editor.log` 累积整个会话的所有编译输出；且文件含空字节，按 UTF-8 直接 grep 会漏。
- **解法**：`Tools/check_compile.sh` —— 先快照字节偏移，**只看新增部分**；读之前 `tr -d '\000'`。
- **教训**：**判断当前编译状态用"新代码里才存在的菜单能不能跑"，不是比对 dll 时间戳、更不是读日志。**

### G-6 Auto Refresh 是关的

- **现象**：`refreshAssets` 之后 C# 没重编译。
- **真因**：`Assets/Refresh` 和进 Play 模式都**不保证**触发脚本编译，必须让窗口**获得一次焦点**。
- **补充**：改 `.mat` / `.shader` / URP `.asset` **不需要**焦点，`refreshAssets` 就立即生效（shader 只重编译着色器，不等域重载）。**所以纯调参可以在 Play 里连续迭代，不必每次退出重编重跑整链** —— 这是本项目后期最高效的工作方式。

### G-7 `GameObject.Find` 找不到 inactive 对象

- **现象**：`setProperty active=false` 之后，再想 `active=true` 恢复时桥报"not found"。
- **解法**：靠退出 Play 回滚，或先确认自己能恢复再隐藏。

### G-8 undo 栈混着所有 MCP 写操作

- **现象**：连续 undo 把更早的改动（如 transform 缩放）一起回退了。
- **教训**：撤销后要复查关键字段。

### G-9 工具参数格式不统一

| 工具 | 坑 |
| ---- | -- |
| `setProperty` | Vector 要传**对象** `{"x":1,"y":2,"z":3}`，传 `"1,2,3"` 报 schema 错 |
| `setComponentProperty` | Color 用 `"r,g,b,a"` **字符串**，枚举用名字 |
| 两者 | Transform 的 `m_LocalRotation` 是 Vector4，**都写不了** → 转欧拉角走 `setProperty` |
| `setMaterial` | 只命中"该对象或其子对象里**第一个** Renderer"，多材质物体无法定向替换 |
| `deleteGameObject` | 参数名是 `gameObjectName`，不是 `name` |
| `createScene` | Additive 模式遇未命名场景会失败 → 用 `NewSceneMode.Single` |
| `addComponent` | 带命名空间的类名不认 → 桥按类名模糊匹配 |

### G-10 多编辑器并存时 MCP 会串台

- **现象**：`unity_getSceneHierarchy` 静默返回了**另一个项目**的场景，`unity_ping` 照样回 pong，完全看不出来。
- **真因**：全局 MCP 配置不带 `--port=`，回落到 6400 打到别人的编辑器。
- **解法**：项目专属端口写进 `.qoder/settings.local.json`；**写操作前先 `getSceneHierarchy` 确认根节点里有本工程的标志物**。
- **注意**：已在跑的 node 客户端**不会**改端口，换端口后要 `/mcp reload`。

### G-11 结构性编辑事故：插入新菜单吃掉下一个菜单

- **现象**：把菜单51/53/54 插到菜单52 之前时，多带了一个类闭合花括号 `}`，导致菜单52 掉到类外。
- **解法**：恢复尾部 + 删掉多余的 `}`（C# 成员顺序无关）。
- **教训**：**在长文件里插代码，锚点要包含下一个成员的完整签名**，不能只锚注释行。

### G-12 复刻视频取帧：接口拉不到就截屏

- **现象**：抖音页面是 JS 空壳、接口全被风控，无法服务端拉流抽帧。
- **解法**：浏览器打开视频 URL → 等播放 → PowerShell `CopyFromScreen` 连拍多帧 → 裁播放区 → 对比分析。

## H.  C# 编译错误速查

| 报错 | 原因 | 修法 |
| ---- | ---- | ---- |
| `CS0234 'UnityEngine.AmbientMode' does not exist` | 文件已 `using UnityEngine.Rendering;` | 写 `AmbientMode.Trilight`（不带 `UnityEngine.` 前缀） |

| `All compiler errors have to be fixed before you can enter playmode!` | 有编译错时 `runMenuItem` **照样返回 ✅** | 先清编译错再判断菜单是否真的跑了 |

## I.  误判记录（我错在哪，为什么错）

> 这一节比任何技术结论都有价值：**错误的诊断会让我在正确方向上持续投入**。

| # | 我当时坚信的结论 | 实际 | 我是怎么被误导的 |
| - | ---------------- | ---- | ---------------- |
| I-1 | "深度纹理没启用" | 深度纹理一直是好的，坏的是取它用的 UV | 诊断数据本身来自 A-1 那个坏通道 —— `screenUV` 恒为 `(1,0)`，取到的是画面右上角的污染值。**用被污染的仪表做诊断，结论一定被污染。** |
| I-2 | "ACES 把画面压暗了" | Volume 从没落盘（B-1），ACES 根本没生效 | 画面确实暗，但原因在别处。**"某个后处理在伤害画面"的前提是它真的在运行。** |
| I-3 | "沙滩太亮，要压暗" | 是**缺蓝**，压暗只会变脏灰 | 只看明度没看色相分布。 |
| I-4 | "远山太亮，要压暗" | 是**色相顺序错**（绿 > 蓝，应为蓝 > 绿） | 同上；而且"压暗"直接得到黑三角剪影。 |
| I-5 | "岩石近黑 = 反照率太低" | 是**环境光被压太低** | 没先量参考帧的"受光/阴影比"（C-2）。改了三轮反照率才想到去看光源。 |
| I-6 | "提 ambient 没用" | ambient 确实提了，但**太阳仰角被菜单54 覆盖**（C-4） | 两个原因互相掩盖，而我假设"我改的就是生效的"。**从没验证过覆盖关系。** |
| I-7 | "碎闪太弱 = 强度不够" | 是**角速度参数把高光限制在极小区域**（D-4） | 强度确实"没起作用"，但我把"没起作用"归因于"还不够大"，而不是"这条路根本没开"。 |
| I-8 | "浅滩灰带是几何问题" | 是**池底色相问题**（D-7） | 连着改了三个几何参数都无效，才想到用排除法。**应该一开始就先定位归属，再修。** |
| I-9 | "沙滩消失了 = 材质不对" | 绕序反了 + 背面剔除，**它根本没被画**（E-1） | 默认"看得见 = 画了"。 |
| I-10 | "荷叶 9-14cm" | glb 在 scale=1 下是 28.4m（F-1） | 沿用了注释里的错单位估算，之后所有尺寸都建立在它上面。 |

### 从这些误判里提炼的三条元规则

1. **先验证观测通道，再验证被测量。**（A-1 / B-1 / B-2 / G-1 / G-2 全是这一条）
   具体做法：做一次**极端值测试**（postExposure 设 -4、颜色设纯红）。画面没变 → 通道不通，别再解释"为什么是这个值"。
2. **改完没效果时，第一反应应该是"我改的东西真的生效了吗"，而不是"还不够"。**
   具体做法：grep 这个属性被写了几次（C-4）；读回资产确认落盘（B-1）；比对截图 mtime（G-2）。
3. **多原因叠加时会互相掩盖，单变量实验失效。**
   具体做法：把耦合系统（光照/后处理/材质）按**固定顺序**分层调 —— 曝光 → 光源 → 反照率 → 色相，每层收敛了才进下一层（C-1）。
