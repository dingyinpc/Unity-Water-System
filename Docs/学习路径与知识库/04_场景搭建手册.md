# 场景搭建手册（04）—— 从零到成品，照着做就能复现

> 目标：在一台干净机器上，把 `Assets/Scenes/Main.unity` 这个"抖音水体视频复刻"场景**完整重建出来**。
> 配套：《03_可复现流程》是**开发日志**（按时间记录每轮改了什么、为什么改）；本文是**操作手册**（按依赖顺序记录怎么做）；《05_踩坑全记录》收录全部陷阱。
> 一句话原则：**所有颜色和参数都由菜单写，不要手改 `.mat`**（见 §7）。
> 范围：本文只管 `Main.unity` 这条**对标视频的复刻线**。另一条按真实潭水写的实验线在 `Assets/Scenes/PondScene.unity`（`Tools/WaterPond/60-69`，64 一条建全场景；65 取带后处理的真实画面、67 导镜像相机 RT、69 像素探针，含森林化；平面反射见《06》第 10 级），另有 Blender 自产树资产的导入与验收菜单 `Tools/Trees/70-73`。**它们不共用本文的菜单，也不替代本文。**

## 2. 最快路径：一条菜单建全场景

**打开 `Assets/Scenes/Main.unity`（或空场景），然后点：**

```
Tools/WaterProject/57 整链重建(按验证顺序)
```

它会按已验证的依赖顺序跑完 **22 个菜单**，约 25–35 秒，结束时把场景标脏。然后：

```
Ctrl+S 保存场景
Tools/WaterProject/26 切换播放(诊断用)     ← 进 Play
Tools/WaterProject/43 Game视图截图(Play中)  ← 出图
```

看 `Docs/screenshots/_gameview.png`。

**用 MCP 驱动的话**（等价，且能自动截图）：

```jsonc
runMenuItem  { "menuPath": "Tools/WaterProject/57 整链重建(按验证顺序)" }
saveScene    { "scenePath": "Assets/Scenes/Main.unity" }
runMenuItem  { "menuPath": "Tools/WaterProject/26 切换播放(诊断用)" }
// 等 ~16s 让 Play 渲染稳定
runMenuItem  { "menuPath": "Tools/WaterProject/43 Game视图截图(Play中)" }
activate_window(Unity)   // ⚠ 必须在截图之后，见 §8
```

> **跑之前先确认 Auto Refresh 状态**：改了 C# 之后必须让 Unity **获得一次焦点**才会编译。判断是否编译成功最可靠的办法是调用一个只存在于新代码里的菜单项，然后看 `Logs/water_probe.txt` 有没有对应输出行——**不要相信 `runMenuItem` 返回的 ✅**。

## 7. 铁律：改完必须回写菜单

**只改 `.mat` 会被下一次整链重建冲掉。** 菜单48（以及 40/42/47）在运行时会把值写进材质资产。

正确流程：

1. **快速试**：直接在 Play 模式里改 `.mat` + `refreshAssets` → 立刻生效、不用重编、不用重跑链。这是最高效的单参数迭代方式。
2. **收敛后**：把最终值**写回菜单48**（颜色/浮点）或对应菜单，再跑一次菜单57 确认能从头复现。
3. **核对**：`Logs/water_probe.txt` 里找 `MENU48 …` 那行，确认无 `MISS`。

同理，**同一个物理量只能有一个写入点**。历史上栽过两次：
- 太阳仰角被菜单48 和菜单54 各写一遍 → 48 的值被静默覆盖；
- `_FresnelPow` 由菜单40 设为 6，而 40 在 48 之前跑 → 必须在 48 里显式覆盖。

## 8. MCP 自动化操作的注意事项

只有走自动化时才需要；手点编辑器可跳过。

| 事项 | 说明 |
| ---- | ---- |
| **截图顺序** | `runMenuItem` 会把 Unity **最小化**，最小化后不渲染、`CaptureScreenshot` 永不落盘。正确顺序：**先跑截图菜单，再 `activate_window`**，被排队的帧会补写出来 |
| **判断截图是否真的更新** | 比对 `_gameview.png` 的 **mtime 有没有前进**。只看菜单返回 ✅ 会把"材质没生效"和"根本没渲染"混为一谈 |
| **`runMenuItem` 永远返回 ✅** | 即使菜单体抛异常、甚至菜单名不存在。唯一可信的是 `Logs/water_probe.txt` |
| **改 C# 需要焦点** | 只有 C# 改动要编辑器获得一次焦点才编译；改 `.mat`/`.shader`/`.asset` 只需 `refreshAssets` |
| **`Editor.log` 有陈旧行号** | 里面是历史所有编译错误。用 `Tools/check_compile.sh`：先快照字节偏移，只看新增部分 |
| **`GameObject.Find` 找不到 inactive** | 一旦 `active=false`，桥就按名字定位不到它了。临时隐藏前先确认能恢复（退出 Play 可回滚） |
| **Play 模式里改场景不一定回滚** | 桥的 `setProperty` 走 `Undo.RecordObject`+`SetDirty`，退出 Play 后**可能仍是改后的值**。临时挪相机做检查后必须读回确认 |
| **Play 中创建的物体不在编辑场景里** | 菜单55/58 若在 Play 里跑，产物退出 Play 就没了。要么在编辑模式跑完再进 Play，要么退出后重跑 |

## 9. 性能预算

细分参数（`_MaxTess 6 / _TessNear 6 / _TessFar 32 / _TessTargetSize 0.35`）是按**目标世界尺寸**自适应的，不是固定细分因子。

- 低机位近水平视角会让整池水面都落进细分近距，历史上 `_MaxTess 12` 直接把 FPS 干到 **0.6**。
- 压到当前值后实测 **30–320 FPS**（RTX 4060 Laptop），1080p 观感下波纹细节没有损失。
- 改机位或改池子尺寸后，务必重新进 Play 看一次 FPS。
