## 7. FAQ / 踩坑记录（持续回填）

| 坑 | 现象 | 解法 |
| -- | ---- | ---- |
| Start-Process 拆参数 | 项目路径含空格时编辑器启动失败退出 | `-ArgumentList "-projectPath \`"路径\`""` 手动加引号 |
| PowerShell 执行策略 | 桥客户端脚本被拒 | `Set-ExecutionPolicy -Scope Process Bypass -Force` 或 `-ExecutionPolicy Bypass -File` |
| createScene Additive 模式 | "Cannot create a new scene additively with an untitled scene unsaved" | 改进桥：改用 `NewSceneMode.Single` |
| addComponent 找不到带命名空间脚本 | "Component type 'X' not recognised" | 改进桥 ResolveComponentType：按类名（不含命名空间）模糊匹配 + 反射异常保护 |
| HLSL float2 用了 .z | `invalid subscript 'z'` | 二维方向量只有 .x/.y，换成 .y |
| HLSL 噪声 du 声明成 float | `invalid subscript 'y'` | `float2 du = 6.0 * f * (1.0 - f);` |
| HLSL 函数内嵌函数定义 | `syntax error: unexpected token '('` | 提到文件作用域 |
| Shader 编译错误卡编辑器 | 编辑器程序集编译失败时桥仍在跑旧代码 | 看 Editor.log 的 `error CS`；修完 refreshAssets 重编译 |
| 场景视角被切走 | 截图一片深绿（是湖底地面） | 设置脚本加"对齐水景视角"菜单项固定 SceneView 取景 |
| SceneView 截图不随取景变化 | Play 模式下 LookAt 后 cam.Render() 仍拍旧画面 | 截图前把 `sv.pivot/rotation/size` 显式应用到相机（桥已修） |
| Play 中重导入 Shader 后画面洋红 | 变体被卸载，材质显示错误色 | 退出再重新进入 Play（避免在 Play 中改 Shader/材质） |
| 俯视角水面一片橄榄绿 | 折射层混合用了平铺系数，俯视时湖底色主导 | 折射混合改为按水深加权（浅水看底、深水看深色水） |
| 水面试图太亮/太暗 | 湖底沙色与折射权重失衡 | `_BaseColor` 用中等棕褐沙 + 折射权重 0.58 |
| deleteGameObject 参数 | 传 `name` 返回 "'gameObjectName' is required" | 参数名是 `gameObjectName` |
| instantiatePrefab 缩放丢失 | 实例化后变 1×1×1 | `instantiatePrefab` 会重置 localScale，须显式传 `scale`（水面 60,1,60） |
| 预制体不含升级后的网格/材质 | 旧预制体引用旧资源 | 升级后重跑"03 生成水体系统预制体"覆盖保存 |
| 网格引用变 null（m_Mesh 丢失） | DeleteAsset 删旧网格 + CreateAsset 重建后，场景里 Water 的 MeshFilter 显示 m_Mesh=null，水不渲染 | 重建后必须 `AssetDatabase.LoadAssetAtPath<Mesh>(path)` 取**资产引用**再赋值给 MeshFilter（内存 Mesh 对象无法序列化） |
| 运行时代码编译失败致 Play 瘫痪 | Update 缺字段声明 → Assembly-CSharp 编译失败 → Play 中所有脚本停摆、FPS 数字冻结在旧值（如 0.5/1.7） | 先查 Editor.log `error CS`；修复后 refreshAssets 重编译，лог 里的旧错误行需对照当前行号分辨 |
| 细分因子与网格基边不匹配 | _MaxTess=12 套到 40m 池塘 0.42m 基边 → 细分到 3.5cm 微型三角形 → 百万级三角形 FPS 崩到 1.7、水体画不出来 | 细分因子改为**目标世界尺寸自适应**：factor ≈ 基边长度/_TessTargetSize（0.25m），任何网格分辨率都收敛 |
| Game 视图自动化截图取不到水体帧 | captureScreenshot game=true 在该 DX11 组合下只返回不透明+天空的帧（立方体/水体都不入帧），Scene 视图帧正常 | Scene 视图取证 + 请用户在编辑器 Game 视图里人工确认最终效果 |
| 桥 `-Params` 偶发 "Expected JSON object" | 某些会话里 ps1 的 -Params 哈希表路径发出去的请求被桥判为畸形（同会话 -Command 正常） | 改用 `-Command '{"id":"..","action":"..","params":{..}}'` 传原始 JSON，最稳 |
| Unity 不识别 .glb | Assets 里放 GLB 只有 .meta，无预制体 | UPM 加 `com.unity.cloud.gltfast`（2022.3 用 6.4.0，6.4.1 不存在会解析失败）→ 重启编辑器让包解析；GLB 以 ScriptedImporter 导入，`.glb` 资产本身就是预制体 |
| UPM 版本写错不报错 | manifest 版本不存在时 lock 不更新、静默失败 | 先查注册表：`GET https://packages.unity.com/<pkg名>` 看 versions 列表再定版本号 |
| 改 manifest 后编辑器不自动解析 | UPM 文件监听不触发 | 改完重启编辑器（启动时强制解析）；或确认 packages-lock.json 出现该包再继续 |
| 荷花素材（免费平替） | 付费包放弃后需免费替代 | poly.pizza 直链 GLB（CC BY 3.0）/ Sketchfab（需登录）/ 中国商店免费款无莲花 → 采用 poly.pizza 两件（Water Lilies + Lotus Flower），摆进圆池 |
| 截图文件内容相同 | 改取景菜单后立即截图拍到旧帧（SceneView 未重绘） | 菜单执行后等 1-2s 再截图；连续两次截图做哈希对比可验证取景确实生效 |
| 水面像"硬币"悬在沙地上方（无厚度） | 水体是纯平面圆盘、沙地顶面低于水面 0.7m、300×300m 无边沙地 | 菜单 12 一键外场景：地面缩小到 60×60m 且顶面抬到水线 y=0；新增池底 PondFloor(y=-1.0，水深1m 折射深度感) + 池壁 PondWall(半径20m 竖壁 0..-1m) |
| 荷叶悬在半空/显得太大 | glb 实例默认 pivot 在水面之上，早期以 y=0.3、缩放 1.5-2.0 摆放 | 荷叶底面贴水 y≈0.03，缩放收到 0.7-0.9；先删旧实例再重放（同名实例 setProperty 只会命中第一个，无法定向改第二个） |
| Cylinder 原语无 MeshCollider | 菜单12 第一版用 `GetComponent<MeshCollider>().enabled=false` 拿到 null 抛空引用，PondWall 未建（按钮仍返回成功） | 改按通用 `GetComponent<Collider>()` 再 DestroyImmediate；运行后必须用 findGameObjects 点名验证实际产物而非只看菜单返回 |
| 复刻视频构图无从下手 | 抖音页面是 JS 空壳、接口全被风控，无法服务端拉流抽帧 | 浏览器打开视频 URL → 等播放 → PowerShell 屏幕截图（System.Drawing CopyFromScreen）连拍多帧 → 裁播放区 → 对比分析（水面占比/绿植带/荷花散点）→ 据此改机位与绿化 |
| 编辑器无响应/崩溃 | GLB 大文件导入与反复编译产生主线程卡顿；本机还装有 UnityCopilot 插件会反复触发重导入 | 先查 Editor.log 尾部（内存 dump=正常退出、crash handler=启动中）；进程只剩他项目编辑器时按 `Start-Process Unity.exe -ArgumentList '-projectPath ... -logFile ...'` 重启，桥 ~10s 恢复后场景仍在（Unity 自动保存 + bridge saveScene 兜底） |
| 改材质后多次截图水面颜色纹丝不动 | ① 会话内材质缓存在重启前不重读磁盘（改 .mat → setMaterial 只重挂缓存实例）② SceneView 超宽画幅下天空/近岸暗水稀释水面均值 ③ 命中旧帧（哈希与调参前完全一致） | 改 .mat 后**重启编辑器**再截（启动强制重导入）；判断画面用带结构的分带均值（如 8 段行带）看颜色分布而不是一条总均值；连续两次截图哈希比对防旧帧 |
| 水面与草地共面 z-fighting | 地面 60×60 顶面 y=0 与水面圆盘 y=0 完全共面 → 陡视角下草地吃掉水面（Game 视图一片绿灰、水面均值被污染） | 菜单15：水面整体上浮 2cm（y=0.02）；荷叶等水面物件相对高度照旧 |
| 主相机 Game 视图看的全是草地 | 主相机默认俯角 -24° 且位近 (0,2.8,-8)，视线压到近岸草地 | 菜单15：主相机改 (0,1.8,-15) 俯角 -1.5° 低机位横贯池塘，16:9 下天空/远岸绿带/水面比例对标视频 |

| 太阳低角度时池塘被树影覆盖 | 树高 6m 主光仰角仅 42° → 环树向池心投 6-7m 长影，整池内侧变暗发灰 | 菜单14：主光仰角 42°→65°（Quaternion.Euler(65,-90,0)），树影收短、全池受光 |
| 水缺乏"透光感"（暗部死黑、无通透） | 原 shader 只有深浅色 Beer–Lambert 渐变，无阳光穿透项、无水体散射 | ① 阳光透射：`sunTrans = pow(saturate(dot(reflect(-V,N), lightDir)), _TransGloss=48)` × `_SunColor × _SunTransmission(0.7) × exp(-gap·_Absorb·0.6)`（透射率指数衰减）；② 体积散射：`_WaterScatter(0.42,0.75,0.88) × (0.3+0.7·(dot(V,light)·0.5+0.5)) × _ScatterStrength(0.38) × (0.35+0.65·trans)`；③ 浅滩补光 `_ShallowColor×_ScatterStrength×0.28×(1-trans)`。参考公式来源：[NVIDIA GPU Gems 1《Effective Water Simulation from Physical Models》](https://developer.nvidia.com/gpugems/gpugems/part-i-natural-effects/chapter-1-effective-water-simulation-physical-models)（波参数关系/色散/陡度上限）+ 通用 Beer–Lambert 透射 |
| 水缺乏"流动感"（看上去是死水） | 细节法线 UV 平移仅 0.12/s（世界位移 ~0.07 m/s），几何波相速 _WaveTimeScale=1 | ① 细节法线平移 0.12/0.09 → 0.42/0.33，反向层 -0.09/-0.12 → -0.33/-0.42（世界流速 ~0.4 m/s）；② _WaveTimeScale 1→1.8（相速 m/s，GPU Gems 式波峰推进）；③ 验证法：同机位间隔 1.6s 连拍两帧，水面区差异像素 >0.5% 即证明流动（实测 5.8%~54%） |
| 水面突然冒出白色大圈 | 演示模式每 0.45s 随机砸一次交互涟漪（strength 0.5-1.0），shader 里交互泡沫以白色 _FoamColor 强叠（×0.4 + foam 混合）成白圈 | ① `WaterInteractionManager` demoInterval 0.45→4s、强度 0.5-1→0.18-0.42；② `_InteractionAmp` 0.35→0.22、`_InteractionFoam` 0.9→0.45；③ shader 尾叠乘数 0.4→0.12 |
| 波浪参数数组不落盘（_Waves 永远是零值） | 该编译配置把 `_Waves` 当**标量** Vector 属性（GetVectorArray 返回长度=1），SetVectorArray 只对第 0 条生效且不持久化 | 波浪参数改为 **shader 内置固定波**（A/ω/Q 硬编码 + `_WaveAmpScale` 幅度旋钮），不依赖材质数组序列化；`∇` 验证：重启后波浪仍在（以前重启后几何波其实是平的，只有细节法线在动） |
| 波浪太整齐/太大（用户："减小一半、有不规则感"） | 固定几波叠加周期重复；幅度全池一致 | ① `_WaveAmpScale` 1→0.5（幅度减半）；② 波数 4→**6**（互不调和的频率/方向/相位叠加）；③ **跨池低频幅值调制** `ampMod = 0.72+0.28·(sin(φm)·0.6+sin(1.7φm+2.1)·0.4)`（φm≈空间57m/34m 周期 + 时间漂移）→ 波浪空间上忽强忽弱、不规则涌动；④ 相位速度 ±10% 漂移打散规律性 |

### 为什么从 rc8 起水面"只剩边框"（两个叠加根因）

1. **退化环**：菜单22 生成水域网格时半径 `r` 没有随圈分数 `rr` 插值（`WaterProjectSetup.cs:1313`），27 圈全部落在同一条岸线半径上 → 每个 quad 面积为 0 → 只剩轮廓。正确写法见菜单20 `Mathf.Lerp(0.4f, S(th), rr)`。
2. **`EditorUtility.CopySerialized(新Mesh, 已存在的Mesh资产)` 只搬 CPU 侧数据**：`vertexCount`/`triangles`/`bounds` 读起来全都正常，但 **GPU 顶点缓冲是空的**，于是一个像素都不画。这就是"换成 URP/Lit 纯蓝也不见任何像素"的原因。改法：`oldMesh.Clear()` 后直接赋 `vertices/uv/triangles`（保留 guid），或新建资产；文件内 14 处同类写法已全部收敛到统一的 `WriteMeshFrom` 助手。
   > 更正：曾把"远山黑锥 / 树带黑锯齿 / 石头黑疙瘩"也归因于此，**实测证伪**——那些是法线方向问题，见下方根因 4。`CopySerialized` 只造成"整块不出像素"，不造成"出像素但发黑"。

> 排查教训：`bounds` 与 `vertexCount` 来自序列化数据，**不能**用来判断网格是否真的能渲染；判据只能是像素。另外相机 y=1.2 时把水面抬到 y=1.5 会抬出视野，"抬升对照法"必须先把目标留在画面内。

### 水面恢复可见之后，又挖出的四个根因（2026-09-18 续）

1. **`PondWall` 是实心内置圆柱**（`菜单12` 遗留，scale `(24,0.5,24)`，顶盖在 y=−0.02）。它的**平盖覆盖了整个半径 12m 的池塘**，于是水下"有效的地面"是这块平板，浅碗 −1.0 的深度被压在它下面完全不起作用，水面离它只剩 4cm → 波谷一穿就破成沙色窟窿。**它的职责本该是"入水沙滩"**，已改为程序化 45° 凹斜坡环 `BeachSlope.asset`（1.10m 水平 / 1.02m 垂直升幅 ≈43°，挂 `Sand_Shore` 材质），池底改为 −1.0 平底盆，净空 1.02m > 波谷 0.59m，破洞消失。
2. **`Mathf.SmoothStep(a, b, s)` 的语义误用**：s 是 **0~1 插值系数**、结果落在 [a,b]，不是"把 s 夹进 [a,b]"。菜单24 写成 `SmoothStep(1.5f, rIn2-1.2f, r)`（拿半径当系数），返回 5.285 这种值，再被 `Mathf.Lerp` 的 Clamp01 吃掉 → y 恒等于 0.02 → **rc9 的"浅碗"从来没生成过**。正确写法：`SmoothStep(0,1, InverseLerp(1.5f, rIn2-1.2f, r))`。
3. **`Trees_Quaternius.glb` 整包内含 5 棵相距上百米的树**：每实例化一次整包，就把另外 4 棵甩到 ±250m 外（探针实测 `NormalTree_5 c=(-244.51,1.40,15.98)`），画面里就是地平线上那排黑色锯齿。修法：实例化后只保留一棵子物体、删掉其余兄弟，再按"目标点 − 保留子物体世界坐标"偏移根节点（菜单21 与菜单24 都已修）。
4. **法线方向导致整片发黑**（与材质无关）：闭合圆顶远山的三角形绕序反了 → `avgNrmY = −0.728`；绿墙网格有重合顶点产生退化三角 → `RecalculateNormals` 留下 **294/582 个零法线**。两者都因 `N·L ≤ 0` 只剩环境光而渲染成黑。修法：圆顶改用镜像绕序；绿墙/沙滩斜坡改为**显式外向法线**（`normalize(径向*0.6 + up*0.8)`）。诊断手段见下方探针。

### 根因 6：水面"棋盘格"不是细分接缝，是噪声梯度不连续

俯视机位下水面出现一格一格的马赛克，第一眼像自适应细分的 patch 接缝。**但域着色器只输出位置、法线是在片元里用 `GerstnerEval(worldPos)` 重算的**，patch 之间不可能产生朝向分块。真因在 `GradientNoise`：它 `return` 的是插值出来的噪声值，而 `out grad` 是

```
grad = float2(du.x*(vb-va) + du.y*(vd-vc),  du.y*(vc-va) + du.x*(vd-vb));   // du = 6f(1-f)
```

这**不是** `n = lerp(lerp(va,vb,u.x), lerp(vc,vd,u.x), u.y)` 的导数，而且 `du` 在格边界恒为 0 → 每格边缘斜率突然归零、格内又很大 → **一个噪声格一个法线朝向** → 画面上的棋盘格。`_DetailScale = 1.6` 时格宽约 0.625m，正好是看到的方块尺寸。

修法（已验证，棋盘格消失）：保留连续的值噪声，斜率改用前向差分——

```
ValueNoise(q)                                   // 与原 n 完全相同的插值本体，连续
NoiseSlope(xz, scale, flow) = (V(q+e)-V(q), V(q+e_y)-V(q)) / e
DetailNormal = 两层 octave(0.7 / 0.5，反向流动) 差分斜率 → float3(-x*_DetailStrength, 1, -y*_DetailStrength)
```

八度、流速、`_DetailStrength` 映射都保持原样，所以波纹性格不变、只是不再有格状接缝。定位这类问题用的就是 `_DepthDebug` 通道输出 + 菜单43/44/45/46 这套工具。

### 根因 7（决定性）：水面发奶白的真因是 `SV_Position` 被当成裁剪空间

从 rc4 到 rc11 水面一直偏奶白，之前所有解释（缺深度纹理 / 泡沫 / 掠射菲涅尔 / 相机太低）**都不是真因**。真因在 `Water_Advanced.shader` 的片元入口：

```hlsl
struct WaterVaryings { float4 positionCS : SV_POSITION; ... };   // 域着色器里赋的是裁剪坐标
...
float4 posCS = IN.positionCS;          // ✗ 片元阶段的 SV_Position 是"像素坐标"，不是裁剪坐标
float4 sp = posCS * 0.5;
sp.xy = float2(sp.x, sp.y * _ProjectionParams.x) + sp.w;
float2 screenUV = sp.xy / sp.w;        // → 恒等于 (1, 0)
```

`SV_Position` 在**片元阶段**语义是像素坐标 `(px, py, z, 1/clip.w)`：`px∈[0,宽]`、`py∈[0,高]`、`w=1/裁剪w`。把它喂进 `ComputeScreenPos` 的公式，分子远大于分母 → `saturate` 后 **`screenUV` 在整个水面上恒为 `(1, 0)`**（画面右上角）。连锁后果：

1. `SampleSceneDepth(screenUV)` 取到右上角**天空**的深度 → `sceneDepth≈0` → **`gap = 0`**；
2. `gap=0` ⇒ `waterBase = _ShallowColor`（浅水色铺满全塘）、`trans=1` ⇒ 体积散射项取最大、`shoreFoam = 0.6·_ShoreFoam` 全域生效；
3. `SampleSceneColor(refrUV)` 也取右上角天空，`col = lerp(col, refrCol, 0.58)` ⇒ **58% 的水面颜色其实是天空像素**。

这三条合起来就是"奶白"，也解释了为什么**怎么调颜色参数都只挪一点点**——参数作用在被常数采样覆盖的分支上。

**定位手法（可复用）**：给 `_DepthDebug` 加第三个模式，直接把 `screenUV` 画出来——`R=screenUV.x, G=screenUV.y, B=rawDepth`。实测水面所有像素都是 `rgb(255,0,10)`，即 `screenUV=(1,0)`、`rawDepth=0.04`，一步定性。之前用"平均色块"读调试图会被巨石/荷叶的实心像素污染，必须用**中位数**或小框（≤1% 面积）。

**修法**：把裁剪坐标另存一份带 `TEXCOORD` 的插值变量（它会做透视正确的插值），`SV_Position` 只留给光栅化器用。

```hlsl
struct WaterVaryings { float4 positionCS : SV_POSITION; float4 clipPos : TEXCOORD3; ... };
o.positionCS = TransformWorldToHClip(gr.pos);
o.clipPos    = o.positionCS;                       // 域着色器里同时写两份
float4 posCS = IN.clipPos;                          // 片元里用 clipPos
```

修完实测：`gap ≥ 4m`、`depthMix = 1.0` 铺满全塘（只剩近岸一圈过渡），水面带从 `(149,182,167)` 直接落到 `(75,146,150)`，参考帧是 `(55,150,165)` —— **同族颜色，不再需要靠调色硬凑**。

**顺带纠正本文档此前的错误结论**：第 288 行"调试输出显示深度纹理是有效的（gap 0.17~2.5m）"**作废**——那组数字本身就是 `screenUV` 恒定造成的假象。深度纹理一直是对的，错的是取它用的 UV。

### 根因 8：水面"突然出现的白色大范围光斑" = 高光无界累加 + 法线频率太低

**先做 A/B 定性**（只改 .mat，不动代码）：把 `_SpecStrength` 与 `_SunStrength` 同时归零，五个水面取样框的均值从 `67 / 80 / 128 / 66 / 76` 收敛到 `68 / 80 / 88 / 73 / 76` —— 最亮框直接掉 40 个点，白斑整片消失。**结论：白斑来自高光项，不是 `_ScatterStrength` 的体积散射泛光。**

两个叠加原因：

1. **高光是"累加"且无界**：`col += mainLight.color * pow(...) * _SpecStrength`。此时 `col` 本身已经被水色 + 散射抬到 0.6~0.8，再线性加一笔就冲破 1.0 → 被硬截成**一片没有细节的死白**（不是"亮"，是"削平"）。
2. **细节法线只有两层低频八度**（`_DetailScale 2.6`、octave2 = ×2.1）。低频值噪声 ⇒ **一大片区域的法线朝向几乎相同** ⇒ 它们同时进入高光波瓣 ⇒ 亮的是"整块"而不是"很多点"。`_SpecPower 150` / `_SunGloss 250` 的波瓣又宽，进一步放大成片。

修法（三处，缺一不可）：

```hlsl
// ① 第三层高频八度：把同朝向的大面打碎成密集小面
+ NoiseSlope(worldPos.xz, _DetailScale * 5.4f, float2(t*0.55, -t*0.47)) * 0.34
// ② 高光改成有界 lerp，水色在高光里仍然透出来，物理上不可能冲破 1.0
float spec = saturate(pow(saturate(dot(N, H)), _SpecPower) * _SpecStrength);
col = lerp(col, _SunColor.rgb, spec);
```
③ 材质侧收窄波瓣并提高波纹频率：`_DetailScale 2.6→6.5`、`_SpecPower 150→420`、`_SpecStrength 0.8→0.55`、`_SunGloss 250→700`、`_SunStrength 0.85→0.5`。

修完五框均值 `72 / 84 / 94 / 66 / 78`（中位 `73~87`），水面带回到 `(74,136,139)`，碎闪变成密集点状。菜单48 的参数已同步，**别再用旧的宽波瓣值**。

> 判据提醒：这类"过曝"不能靠肉眼看截图定性——`lerp` 有界后即使 `spec` 饱和也只是偏奶油色而非纯白，视觉上不再刺眼但均值仍会偏高，必须用 `Tools/sample_png.ps1` 的多框**中位数**对比。

### 根因 9：放大后"发糊、不透彻" = 透明权重被关死 + 折射位移过大

用户反馈两件事：**放大看模糊、没有水的透彻感**；**光斑仍然在，但太大、突兀**。两条独立成因：

**（1）透彻感**：水面"看穿到湖底"只有两条路，而当时两条都被关死了。

```hlsl
col = lerp(col, refrCol,  (1-fres) * (1-depthMix) * 0.58);   // ① 折射：depthMix 已=1 → 权重≈0
col = lerp(col, sceneCol, (1-fres) * (1-_Opacity));          // ② 未偏移的清晰采样：_Opacity=0.95 → 只剩 5%
```

`sceneCol` 是**未经位移**的场景采样，也就是" crisp 的湖底"，却被 `_Opacity` 压到 5%；同时 `_MaxUVOffset = 0.12`（折射位移上限，**按屏幕比例算**，906px 宽时可达 ~108px）让任何折射都糊成一团。结果水面像蒙了一层色膜。
→ `_Opacity 0.95→0.78`、`_MaxUVOffset 0.12→0.025`、`_RefractStrength 0.55→0.3`、`_ScatterStrength 0.55→0.45`（奶白泛光）。

**（2）光斑太大**：波瓣太宽 + 法线以低频为主。
→ `_SpecPower 420→900`、`_SunGloss 700→1500`、`_SpecStrength 0.9→0.65`、`_SunStrength 0.85→0.55`；并把 `DetailNormal` 三层八度权重从 `0.70/0.50/0.34` 改成 **`0.40/0.55/0.50`**（削弱最粗那层的大平片，能量给高频）。

**副作用与修正**：以上一起把亮度从 `(54,143,153)` 打到 `(27,92,102)`。**不要用高光或散射去补亮度**（会把刚收窄的光斑重新撑回去），要提**水色本体**：`_DeepColor → (0.09,0.62,0.78)`、`_ShallowColor → (0.28,0.75,0.72)`，回到 `(36,135,148)`~`(70,163,179)`。

> **⚠ Play 模式里改场景不一定会回滚。** 本轮在 Play 中用桥把 `Main Camera` 挪到 `(0,1.6,-5.5)` 做放大检查，**退出 Play 后它仍是这个值**（桥的 `setProperty` 走了 `Undo.RecordObject` + `SetDirty`）。凡是临时改相机/物体做检查，退出 Play 后必须**读回属性确认**并手动改回，再 `saveScene`。

### 根因 10：沙坑"看不出凹陷" = 平底盆没有深度梯度，靠多物体分层解决

用户指出：凹陷完全读不出来，并允许"不必只用一个物体"。诊断出三条同时成立的原因：

1. **盆底是 `y=-1.0` 的死平面**（rc12 为了保 1.02m 净空刻意做平）→ 整片水深一致 → 透明水面下看不到任何明暗变化，**凹陷需要梯度**。
2. **入水坡只有 1.10m 宽、45°**（`BeachSlope`）→ 像浴缸壁，不像沙坑；而且它整个藏在水下，岸上看不到过渡。
3. **水下没有分色**：盆底和干沙滩同一个 `Sand_Shore` 亮色 → 缺少"湿沙比干沙暗"这一条最直观的线索。

菜单52 用**四个物体**分层解决（全部程序生成、非索引化→逐面法线→平面着色）：

| 物体 | 作用 | 参数 |
| --- | --- | --- |
| `PondBasin` | 锥形盆底，中心 −1.30 → 岸边 +0.02 | 指数 `Pow=1.55`：盆底趋平、向岸坡度最大（沙坑的正确剖面）；`seg=128 × rings=34`，26112 顶点 |
| `BasinStep_00/01/02` | 三圈同心台地，各自略高于盆底 | 带参 t∈[0.34,0.46]/[0.56,0.68]/[0.76,0.88]，抬升 `0.055+0.075t`，形成向内陡坎的明暗边 |
| `Sand_Wet` 材质 | 盆底用明显更暗的湿沙 | 线性 `0.20,0.155,0.105` |
| `Sand_Damp` 材质 | 台地用半湿中间色 | 线性 `0.34,0.275,0.190` |

配合已有的 `Sand_Shore` 干沙亮色，形成 **干→潮→湿** 的同心分色带，凹陷一眼可读。旧件处理：`PondFloor` 沉到 `y=-1.9` 当兜底（防新盆有洞穿帮）、`PondWall` 的 MeshRenderer 关掉（45°窄壁会盖掉缓坡读感）。

> **⚠ 第一版翻车点：台地是正圆 → 变成"靶心"。** 等参数 t 生成的同心环过于规则，看着像体育场或波纹槽，完全不像挖出来的沙坑。
> 解法是加 `WobA(th, seed)`：三组正弦（2θ/5θ/9θ，相位取自 `Hash11`）合成 **平滑**角向扰动（±约0.10 的 t 单位 ≈ ±1.3m），同时作用于**盆底等深线**与**台地边界**，让两者沿同一套扭曲轮廓走，不会互相错位穿帮。
> 教训：程序化地形要"不规则"，但必须用**低频平滑函数**扰动；直接叠逐顶点随机噪声会变成麻点。
>
> **⚠ rc19 修正本条的台地参数**：水面透明度提上来之后（见根因 12），这三圈台地的外缘每一次都是**深度突变**，在近岸画出笔直的灰白分界线。抬升量 `0.055+0.075t → 0.028+0.042t → 最终 0.010+0.016t`（约原值的 1/5），凹陷改由锥形盆底单独承担；`Rim` 也从 `+0.02` 压到 `-0.07`，让盆体外缘**低于水面**（原先与水面共面，水一变透就破水而出）。

### 根因 11：整幅比参考暗 ~8 倍（线性）= 三个旋钮同时往低处拧，最后被 ACES 趾部吃掉

参考帧实测：阴影里的岩石 `med(88,122,151)` 和受光的岩石 `med(103,130,154)` **几乎相等**（差不到 1.2 倍）。这不是"对比度低"，而是**天光填充极强**——直射光只贡献很小一部分，整个场景接近平涂。我们当时是 `postExposure 0.55` + ambient sky `0.22,0.27,0.335` + 太阳仰角 `14°`，实测同一处岩石 `(30,41,53)`，线性亮度差约 8 倍。

三条原因叠加，且**互相掩盖**，单独调任何一条都看不出效果：

| 旋钮 | 错在哪 | 修正 |
| --- | --- | --- |
| `postExposure 0.55` | ACES 的趾部把低段进一步压平，中间调落在趾部里就全成黑的 | `→ 1.15`（×1.5 倍线性） |
| ambient sky `0.22` | 参考帧是平涂风，天光才是主光源 | `→ 0.50,0.58,0.68` |
| 太阳仰角 `14°` | 朝上面 `N·L = sin14° = 0.24`，岩石顶/树冠/沙面**集体失光** | `→ 30°`，强度 `1.95 → 2.5` |

> **⚠ 最坑的一点：太阳仰角有两个写入点。** 菜单48 设 `Euler(28,205)`，菜单54「视频低机位」为了保碎闪又设 `Euler(14,208)`。重建链里 54 在 48 **之后**跑，所以菜单48 的值被静默覆盖——我据此反复怀疑"ambient 提了没用"，其实是太阳一直没提上去。
> 修法不是把 54 的数也改成 30，而是**删掉菜单54 对太阳的赋值**，让菜单48 成为唯一来源。
> 教训：**"几何耦合"不等于"要重复赋值"**。碎闪确实依赖太阳仰角与相机俯角的配合，但正确做法是让俯角去适配那个仰角（菜单54 改为 `Euler(20,9,0)`），而不是在两处各写一遍同一个物理量。同类问题本轮还抓到一次：`Hill_Distant` 和 `_SkyHorizon` 只改了 `.mat` 没写回菜单48，下一次整链重建就会退回旧值——已全部补写进字典。

### 根因 12：水"不透"且近岸比塘心还暗 = 吸收系数作用在视深上，而池子只有 1.3m

`Water_Advanced.shader` 里 `gap = sceneDepth - waterDepth`，两者都是 `LinearEyeDepth`，所以 **gap 是沿视线的距离，不是垂直水深**。而 `depthMix = 1 - exp(-gap * _Absorb)`，`_Absorb = 1.9`。

池底最深才 −1.30m。取 gap≈1.3 就已有 `depthMix = 1-e^{-2.47} = 0.92` → **全池都被判定为深水**，浅滩也一样。后果有两个，且方向相反，所以之前一直误判成"颜色调得不对"：

- 近岸浅水本该最亮（沙底透出），却和塘心一样取 `_DeepColor` → 近岸反而更暗；
- 参考帧正是相反：**近岸淡薄荷绿、塘心才转青**。

| 参数 | 旧 | 新 | 理由 |
| --- | --- | --- | --- |
| `_Absorb` | 1.9 | **0.85** | 让 1.3m 处 depthMix≈0.67，浅滩保留浅水色 |
| `_Opacity` | 0.78 | **0.76** | 提高湖底权重，但别过头（沙底会把水色洗淡） |
| `Ground_Lake` | 暗绿 `0.105,0.235,0.120` | 浅沙 `0.28,0.34,0.190` | 参考帧的池底是沙；**绿必须反超红**，否则折射出来的浅滩是灰的 |
| `Sand_Wet / Sand_Damp` | 暗褐 | 偏黄绿 | 同上，折射层会把沙底大量混进水色 |

> **踩坑记录：浅滩那条灰白带不是几何问题。** 我先按"盆缘破水"改了 `Rim`、又按"台地硬边"砍了抬升量，都无效；再按"过曝"压沙色，也无效。最后用**排除法**：在 Play 模式里 `setProperty active=false` 逐个隐藏 `Ground` / `PondBasin` / `BasinStep_*`，画面里那条带**完全不动** → 说明它根本不是独立物体，而是水本身。
> 真正的判据是：改 `_ShallowColor` 时它**跟着变了**，说明归水管。剩下的是色相问题（沙底偏红 → 混出来发灰），不是几何问题。
> 对照参考帧后确认：**构图A 底部本来就有这样一条浅色浅滩带**，我们只是颜色不对。差点为了一个不存在的问题重构盆底。

> ```
> 子节点的 `position` getter 会实时反映父节点的新矩阵，所以拿它当锚点天然正确。

### 根因 14：碎闪"点不亮"不是强度问题，是**掠射反射根本没建立**

参考帧的碎闪是一整片近白高光场 `med(208,218,201)`，我们同一位置只有 `(69,149,171)`。第一反应是"高光不够强"，于是连着抬 `_SpecStrength 1.1→1.7→2.0`、`_SunStrength 1.4→2.6→3.4` —— **几乎没用**，实测只爬到 `(95,177,175)`。强度不是瓶颈，角度才是：

| 参数 | 当时的值 | 它实际做了什么 | 修正 |
| --- | --- | --- | --- |
| `_SunGloss` | 700 | `pow(cosδ, 700)` 半高宽仅 **±1.8°**，太阳高光被压成画面里一条细线，不是"一片" | `→ 90`（±约10°，摊成一条带） |
| `_FresnelPow` | 6 | 水面俯角 10° 时 `fres` 才 **0.33**，要贴着地平线才趋近 1 ⇒ 画面里绝大部分水面**压根没在照镜子**，`col += skyCol*fres*_SkyReflect` 这条路径基本不成立 | `→ 4` |
| `_SkyReflect` | 0.55 | 即使 fres 到位也只反射一半强度 | `→ 1.0` |

> **判据**：怀疑"某个高光项太弱"之前，先算它在**画面那个位置的几何条件下**能取到多少。`pow(cosδ, n)` 的半高宽约 `1.3/n` 弧度 —— n=700 时不到 2°，而 52° 视场里 2° 只占 4% 高度。再大的强度乘在 4% 覆盖率上也是一条线，不是一片。
> 反过来，放宽角度会摊薄亮度，所以 `_SunStrength` 从 3.4 **降回** 2.2：覆盖面积涨了约 8 倍，强度必须让一步，否则整幅洗白。
> 之所以这次敢放宽波瓣而不重蹈根因 8（整块死白），是因为细节法线已经是三 octave、`_DetailScale 7.6`，面元足够小足够密 —— 放宽只会让点变多变亮，不会连成一片平面。**"波瓣宽 = 光斑大"这个结论只在法线低频时成立。**

> **⚠ `_FresnelPow` 差点被链尾改回去**：它由菜单40（rc4 水面基准）设成 6，而菜单40 在菜单48 之前跑。只在 `.mat` 上改成 4 的话，下一次整链重建就会退回 6 —— 这正是根因 11 抓到的"两处写同一个物理量"的同一个病。已在菜单48 里显式补一行覆盖，并注释说明来源。

### 根因 15：远岸"空"与"树拖黑影"

- **卵石等于没撒**：菜单58 第一版给 0.055~0.175 的缩放（实际直径 0.12~0.39m）。参考帧远岸在画面里距相机 20~25m，那个尺寸只有 **1~3 像素** —— 撒了 179 颗，画面里完全看不见，看起来仍然"光秃"。改成 0.16~0.40（直径 0.35~0.9m）后一眼可数。**程序化散布一定要按"它在画面里占几个像素"反推尺寸**，不是按米。
- 另外补了 5 簇专门落在 θ≈π/2（+z 一侧）：相机 yaw 9° 意味着视线朝 +z，均匀绕圆撒的话密度全花在画面外的近岸和两侧。
- **远树拖长黑影**：太阳仰角 30° + `m_ShadowDistance 140` 把 r30~50 的树全收进阴影范围，每棵都在草坡上画一道长条暗纹，参考帧远岸没有这种条纹。菜单56 里对这些 Renderer 统一 `shadowCastingMode = Off` —— 这个距离上它们只需要读成灌木剪影，不需要自投影。

  **已测得的结论（不再是假设）**：
  - 调试输出（shader 新增 `_DepthDebug`，菜单44 开关，R=gap/4 G=depthMix B=fres）显示**深度纹理是有效的**：水面像素 gap 约 0.17~2.5m、depthMix 约 0.05~0.55。"缺深度纹理"这个假设作废。
    > **⚠ 本条已被根因 7 推翻**：那组 gap/depthMix 数字本身就是 `screenUV` 恒为 `(1,0)` 时从画面右上角取到的污染样本，既不能证明深度纹理有效，也不能证明无效。深度纹理一直是好的，坏的是取它用的 UV。保留此条只为记录误判过程。
  - 泡沫 A/B（把 `_CrestFoam`、`_ShoreFoam` 直接归零，不改代码只改 .mat）：水面带 `(158,221,227) → (131,206,219)`，只挪了 R−27/G−15 → 泡沫是**次要**贡献。
  - 剩下的是一笔**近似均匀 +0.25 的全通道抬升**，与 `col += skyCol * fres` 这一项吻合：调试图里水面 `fres ≈ 0.42~0.54`。原因是主相机在 y=1.2、俯角 −2.5°，**掠射**看水面；而参考帧的相机是**向下俯看**水塘的，`dot(N,V)≈0.6 → fres=pow(0.4,6)≈0.004`，天空反射几乎为零，深水色自然占主导。
  - 所以真正的两个杠杆是：**① 把机位抬高/俯角加大**（改构图）；**② 给 shader 加一个可标度的天空反射权重**（改着色模型）。继续拧颜色参数是无效方向。
  - 新增工具：菜单43（Play 中 `ScreenCapture` 取真实 Game 视图；注意**编辑器失焦时 Game 视图不呈现，截图不会落盘**）、菜单44（切换 `_DepthDebug`）。
- `23` 是**按材质名**重挂（`Materials/<m.name>.mat`），所以给新物体换材质时，只要该材质资产存在，跑 23 不会被改回去。
- 探针 `37 水面渲染探针(写文件)` 把实况写到 `Logs/water_probe.txt`：**桥没有 Console 回读通道**，`Debug.Log` 读不回来，需要文件回读；它同时输出各渲染器世界包围盒与 `avgNrmY/zeroNrm` 法线体检。
