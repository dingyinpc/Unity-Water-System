> 立项时间：2026-10-24。本文档是**完全复刻阶段（阶段6）的总案**：差异盘点 → 五个大步骤 → 每步的验收标准。
> 事实源：《08_参考视频知识点全解》（15 章 38 卡逐卡转录）；已完成进度见《09》与《版本更新计划》（P0~P2 + 风格线 + 泳池线全绿）。
>
> **人话版**：参考视频一共 15 段内容。我们对过一遍：有 9 段已经做完而且验收过，有 6 段有缺口。
> 最大的两个缺口：① UP 主的海是"FFT 数学海"，我们的是"手搓波纹海"——整条技术线没有；② UP 主的云是
> "三维体积云"（有厚度、分层漂、被太阳照），我们的是"贴在天上的平面图"——所以云的速度、位置怎么看
> 怎么不对，这不是调参数能救的，要换做法。接下来分六轮大活：先造"量动画的尺子"（3 秒逐帧对比），
> 再补 FFT 海（新场景），再换体积云+天空+镜头光晕，再升级远景雾，然后把量出来的小毛病攒一起集中修，
> 最后总验收+收尾。每轮都是长时间工作，做完你能立刻看到大片级别的变化。

## 0. 目标与边界

**目标**：我方作品集与视频作品集达到 **100% 内容对应** —— 视频里出现过的每一个可演示效果，我们都有一个**同类、动态特征对齐、静态指标同档**的对应场景/模式。

**边界的诚实声明**：
- UP 主的网格参数、噪声贴图、配色数值不公开 ⇒ "100% 相似"指**逐段动态判据 + 静帧三指标 + 目视同类**全部达标，不是逐像素相同；
- 复刻对象是**水体与空境的行为**，不含运镜复刻（对比用同类型固定机位）；
- 视频里的"参数调节过程"（如 S2 关/开水平位移）复刻为**演示开关**，不逐帧复刻调节动画。

## 2. 六个大步骤（R1–R6）

> 排序原则：先造尺子再干活（R1）；三个大件按缺口大小排（R2 FFT 海、R3 体积云、R4 雾）；
> 大件之间不动参数级小修（会被重写冲掉），小差距项登记造册攒到 R5 集中清账；R6 总验收收尾。
> 每步 = 一轮长时间工作，结束时有**大量可见变化**（新场景/新天空/新氛围/违和感统一消失/总验收报告）。

### R1 · 动态对比基线（先造尺子）——"3 秒逐帧对比"落地

**做什么**：
1. **我方连帧采集**：Play 内运行时采集组件（每帧抓取 → JPG 序列落盘 `Docs/screenshots/seq_<场景>_<标签>/`，1920×1080，≥3 秒 ≈ ≥90 帧；JPG 而非 PNG 保证不掉帧），菜单化（`Tools/Seq/…`），支持"正常速/冻结"两种采集；
2. **参考侧动态特征表**：从 `metrics.csv` + 帧对差分，产出视频每段的四判据基准值（见 §3 协议），落 `Docs/视频逐帧/f1083870/analysis/dynamic_baseline.csv`；
3. **对比工具** `Tools/Video/seq_compare.py`：输入我方帧目录 + 参考帧区间 + ROI（天空/水面/近岸），输出：帧差曲线叠图、判据表（通过/不通过）、并排交替联络表；
4. **首轮基线报告**：五场景各采 3s，跑出与参考对应段的差距排行——**云速/波速/闪烁主频各差多少倍**，作为 R2/R3/R4 的调参靶子。

**可见变化**：第一份"动起来差在哪"的量化报告 + 对比曲线图。
**验收**：① 工具能一次跑通五场景；② 报告给出每场景四判据数值与参考比值；③ 云速差距有实测数字（用户点名问题的定量版）。

### R2 · FFT 多级海洋新场景（最大缺口，S1/S2/S5/S7）

**做什么**（新场景 `FFTScene`，前缀 `FFT*` 防资产冲突）：
1. **频谱生成**：ComputeShader 生成 PM 谱 `h0(k)`（风况/风向/方向扩展），初始频谱只算一次；
2. **时间演化**：`ω=√(gk)` 深水色散，每帧更新相位 `e^{±iωt}`（60Hz 固定步长 + 时间倍率，统一时钟）；
3. **IFFT 落地**：两维 IFFT → 位移 RT（Y=波高，XZ=choppy 水平位移）+ 梯度 RT；多级（2~3 级 k 尺度）按世界坐标权重合成（近密远连）；
4. **水面 shader**：世界 XZ 采样位移 RT 顶点形变 + 梯度叉积重建法线 + choppy 开关（S2 演示）+ 浪峰增强模式（S5）+ FFT 焦散演示模式（S7，波高梯度投影到池底式平面）；
5. **接线**：菜单 `Tools/FFT/…`（建场景/参数/演示开关/取帧），复用 GameViewCapture + R1 连帧采集。

**可见变化**：全新的数学海——大范围涌浪 + 近处细浪，可开关水平挤压/浪峰/焦散。
**验收**：① 色散抽测：跟踪单一波长波峰速度 vs `√(g/k)` 理论（误差 ≤10%）；② choppy 关/开 A/B 差异 ≥5% 像素；③ R1 四判据对参考 S1 段全部达标（§3）；④ 目视：远处无平铺重复、近处高频细腻。

### R3 · 体积云 + 天空渐变 + LensFlare（用户点名的云，S11–S14）

**做什么**：
1. **全局体积云**（Sky 升级）：视线与云底/云顶**球壳**求交得 RayMarch 区间，场景深度截断；fbm+细节噪声密度场；**风向/风速/风切变**（上下层位移差，"分层漂移不重叠"）；深度感知上采样 + 历史混合抗闪；昼夜两套受光（日出日落云缘向环境色过渡）；
2. **云速对齐**：R1 已测参考云速（px/s→m/s），把风参数定标到参考档（不再手调 `_CloudDrift`）；
3. **分层天空渐变**（S12）：地平线/低空/中空/天顶 4 层色，ViewDir.Y 逐层混合；朝阳面/夕阳面两组渐变按 `dot(view, sunDir)` 混合；Trilight 三色随昼夜曲线联动；
4. **LensFlare**（S11 C22）：黄昏型（大红斑）与白天型（小亮点+鬼影）按太阳高度交叉插值，受云/雾可见度调制；
5. **云影 RT 升级**（S14）：从体积云 RayMarch 顺路落 Beer-Lambert 透射率 RT，水面 GGX 高光 × 云影透射率（替换现有 2D AtmosphereField 云影源）。

**可见变化**：所有场景的天空整体换新——有厚度的云、贴地平线的球壳轮廓、日落被染色的云缘、云过太阳时水面高光实时变暗。
**验收**：① **云速比** ρ_v ∈ [0.7, 1.4]（对参考实测，用户点名项）；② 云影关/开 A/B 差异 ≥2% 像素（正午档）；③ 体积云开关场景 FPS 不低于现状 80%（性能护栏）；④ 昼夜循环下云色/天空/LensFlare 无跳变（连续性判据）；⑤ R1 四判据对参考 S13/S14 段达标。

### R4 · 远景雾升级（S15）

**做什么**：
1. RayMarch 雾：视线与球形雾区求交定采样区间，密度场 = triplanar 2D 噪声加权 + 3D 细节噪声，SmoothStep 边界 → **非均匀 3D 雾团**（不再是均匀指数雾）；
2. **雾遮太阳**：按雾区起终点/高度估算太阳透射率，与云影透射率**串联**进水面 GGX：`sunIntensity × cloudTrans × fogTrans`——雾遮太阳时水面高光跟着衰减；
3. 天空判定沿用线性深度阈值 + SmoothStep（水面反射共用）。

**可见变化**：晨雾团贴水面、远景沉进雾里、太阳被低雾遮住时整片高光暗下来。
**验收**：① 3D 雾团目视可见（雾团结构非均匀）；② 雾遮高光 A/B 差异 ≥2% 像素；③ R1 四判据对参考 S15 段达标。

## 3. 验收标准 · "3 秒逐帧对比"协议（所有大步骤共用）

**采集**：
- 我方：Play 正常速（timeScale=1），连帧 ≥90 张（≥3s @30fps 等效），1920×1080 JPG 序列；
- 参考：对应章节的连续 ≥90 帧（960×432 原生）；
- 双方各取 ROI（天空带 / 水面带 / 全画面）分别算。

**四条动态判据**（每段每 ROI 一行，通过=全部达标）：

| # | 判据 | 定义 | 通过阈值 |
| --- | --- | --- | --- |
| D1 运动能量同档 | ρ_E = mean(Δluma_我方) / mean(Δluma_参考) | 相邻帧亮度差均值比 | 0.5 ≤ ρ_E ≤ 2.0 |
| D2 时间连续性 | spike = max_i \|Δluma_i − median\| / σ | 帧差序列无孤立尖峰（跳变/爆闪） | spike < 3 |
| D3 特征速度尺度 | ρ_v = v_特征_我方 / v_特征_参考 | 云边缘/波纹/涟漪的位移速度（追踪测量） | 0.7 ≤ ρ_v ≤ 1.4 |
| D4 闪烁主频 | ρ_f = f_主峰_我方 / f_主峰_参考 | ROI 亮度时间序列的频谱主峰（碎闪节奏） | 0.6 ≤ ρ_f ≤ 1.67 |

**静帧三指标**（沿用 R08 方法）：亮度 / 对比度 / 饱和度与参考同档（各自 ±25% 或落在参考段自身波动范围内）。

**通过规则**：一段 = 四动态判据 + 三静帧指标全过；一个大步骤 = 其目标段全过 + 性能护栏不破（FPS ≥ 现状 80%）。

**工具落位**：我方采集 = R1 的连帧组件（菜单触发）；对比 = `Tools/Video/seq_compare.py`；参考基准 = `analysis/dynamic_baseline.csv`（R1 产出）。**纪律**：同会话采集对比（天空/云吃 `_Time.y`，跨会话差 0.06%~5%，已有实测教训）。

## 4. 云专项（用户点名，先立此存照）

**现状**：`Sky_Coast` 的云 = 视线投到固定高度平面的 fbm（4 倍频各自漂移，`_CloudDrift=0.010` 手调）。
**问题定性**：平面云没有厚度/分层/受光结构 ⇒ 速度感、位置感、与太阳的联动天生出不来；历史上"云太快降一半"式的手调治标不治本。
**解法**：R3 换体积云（球壳 RayMarch + 风切变），云速用 R1 实测的参考值定标（D3 判据把关），不再手调。

## 5. 风险与依赖

1. **FFT 的 IFFT 成本**：Unity ComputeShader 无现成二维 IFFT，需自写（stockham 或两级一维）；若 compute 受阻，退化方案 = CPU FFT 每帧写 RT（256² 可行，先跑通再优化）——写进 R2 的第一里程碑；
2. **体积云性能**：半分辨率 RayMarch + 深度感知上采样是视频同款省法，性能护栏（FPS ≥80%）不达就降档（步数/分辨率）；
3. **R2/R3 都是大件**：各自内部按"里程碑+验收"推进（R2：谱→IFFT→水面→多级→演示模式；R3：体积云→风→天空渐变→LensFlare→云影），每里程碑落探针/截图取证，防"大而无证"；
4. **时间顺序不可倒**：R1 必须最先（后面所有验收用它）；小项修复必须等三个大件（R2~R4）落地后再做（R5）；R6 必须最后；
5. 参考素材（原片/5568 帧/metrics.csv）**不入库**（gitignored），所有报告里引用帧号+数值，不贴大图进 git。
