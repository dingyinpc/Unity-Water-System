## 0. 水面到底是什么

水面不是"一张蓝色贴图"，而是一个**随时间变化的二维曲面 + 光学响应**：

- **几何**：一个平面网格，顶点高度被波函数改变（位移），于是有了起伏与浪。
- **光学**：水面是半透明介质 → 既有反射（天空、环境高光），又有折射（水下物体的光路偏移），还有吸收（越深越暗）。
- **于是**：画水面 = ① 算出每个顶点的位移与法线 → ② 用法线做光照/高光 → ③ 把折射采样的画面叠加进来 → ④ 加泡沫/波纹细节。

水面表达的三种方式（按成本/精度）：

| 方式 | 精度 | 成本 | 本项目 |
| ---- | ---- | ---- | ------ |
| 数学函数（解析波） | 高（法线可求导） | 低 | ✅ 格斯特纳波 + 程序 ripple |
| 高度图/法线贴图 | 中（需差分） | 低 | RNW 细节法线用 |
| 流体仿真（FFT/网格） | 最高 | 高 | 不做（Tessendorf FFT 列为延伸） |

## 1. 格斯特纳波（Gerstner Wave）

### 1.1 为什么用它
正弦波只会"上下起伏"，浪尖圆滑、没有卷曲；**格斯特纳波在竖直方向之外还加水平位移**，
让波峰前倾、波谷拉开，形成真实的"卷尖浪"（crest）。这正是视频里"浪尖效果"的几何基础。

### 1.2 公式（GPU Gems 1 Ch.1，深水模型）
对第 i 条波（方向 D_i、振幅 A_i、角频率 ω_i、陡度 Q_i、相位 φ_i），
在静水面 X = (x, z) 处的位移（世界XYZ）：

```
P(x,z,t).x = Σ_i  ( Q_i · A_i · D_i.x · cos( D_i·X·ω_i + φ_i·t ) )
P(x,z,t).z = Σ_i  ( Q_i · A_i · D_i.z · cos( D_i·X·ω_i + φ_i·t ) )
P(x,z,t).y = Σ_i  ( A_i · sin( D_i·X·ω_i + φ_i·t ) )
```

- D_i = 波传播方向的单位二维向量；X = 平面位置。
- ω_i = 2π / L_i（L_i 为波长）；波速 v_i = sqrt(g / k_i)（深水色散，g≈9.8）。
- Q_i ∈ [0,1]：陡度。"1"是极限（浪尖最尖）。多个 Q 需满足 **Σ(Q_i·A_i·ω_i) ≤ 1** 否则顶点回绕打结。

### 1.3 法线（关键！解析求导）
对 x、z 分别求偏导得到切向量 T、副切向量 B，再叉积得法线 N：

```
T = (1 - Σ Q_i A_i D_i.x² cos_i,   Σ A_i D_i.x ω_i cos_i,  -Σ Q_i A_i D_i.x D_i.z cos_i)
B = (-Σ Q_i A_i D_i.z D_i.x cos_i, Σ A_i D_i.z ω_i cos_i,  1 - Σ Q_i A_i D_i.z² cos_i)
N = normalize(cross(B, T))
```

（cos_i = cos(D_i·X·ω_i + φ_i·t)；这里 D_i.x/D_i.z 在世界系展开。）
好处：**法线与位移来自同一个函数，永远一致**——这是"RNW 法线混合"里解析法线的来源。

### 1.4 典型参数（四条波，频率递增、振幅递减）
| 波 | 波长 L | 振幅 A | 陡度 Q | 方向 |
| -- | ------ | ------ | ------ | ---- |
| 1（主浪） | 8~12m | 0.4 | 0.7 | 风向为主 |
| 2 | 4~6m | 0.2 | 0.8 | 偏转 ±20° |
| 3 | 2~3m | 0.1 | 0.8 | 偏转 ±45° |
| 4（细节） | 1~1.5m | 0.05 | 0.9 | 随机 |

### 1.5 Unity 落点
- 顶点阶段（Vertex/Domain Shader）计算位移；片段阶段用法线。
- 时间参数：`_Time.y`；为稳定动画用 `frac(_Time.y)` 也行。
- 性能：4 条波 × 三角函数 ≈ 微不足道；不要复制到整个屏幕全屏网格上,而是放在**被细分的网格**上（见 §2）。

## 2. 自适应曲面细分（Adaptive Tessellation）

### 2.1 为什么
格斯特纳波要"看得清"，网格密度必须足够（近处 1 米见方细小波浪也要几十个顶点）。
如果整片湖面都用高密度网格，顶点数爆炸。**自适应 = 近处密、远处疏**，只有靠近相机的部分被拆细。

### 2.2 硬件管线（DX11）
```
Hull Shader  (按三角形三个边 输出细分因子)
    → 硬件 Tessellator（按因子切分三角形）
    → Domain Shader（对每个新顶点：插值、求位移、输出位置）
```
顶点着色器只管原网格顶点；Domain Shader 处理**生成的所有新顶点**——格斯特纳波的位移就写在这里。

### 2.3 自适应判据（两种常用）
1. **距离判据**：`factor = clamp(k · maxTess / distance, 1, maxTess)`——近密远疏，简单稳定。
2. **屏幕空间误差判据**（HZD 思路）：把边长投影到屏幕，按"屏幕像素误差"反推细分：
   `edgeLenPx = length(project(edgeV0) - project(edgeV1))`；
   `factor = clamp(edgeLenPx / desiredPixel, 1, maxTess)`。视觉质量恒定、与分辨率无关。

### 2.4 Unity/URP 落点（注意事项）
- **URP 用 Surface/URP Lit Shader 时 CPU 端 tessellation 不可用**，必须写**原始 HLSL**：
  `[UNITY_domain("tri")]` Domain Shader、Hull Shader 内输出 `TessellationFactors`
  （`SV_TessFactor` ×3 边 + `SV_InsideTessFactor`）。
- URP 下需用 `Varyings` 全手动管线；`_ScreenParams`、`unity_CameraProjection` 可用。
- 平台：桌面 DX11 / Vulkan 支持；移动端一般**关闭**（或不依赖 tessellation 观感）。
- 兜底：关闭时近处细化靠"跟随相机锁定高度的细分网格 + 顶点抖动"近似（本项目不实现，记录为可选）。

## 3. 屏幕空间折射（Screen-Space Refraction）

### 3.1 原理
真实折射要先求光线穿过水面后与水下场景的**求交**，成本太高。
屏幕空间折射的近似：**把"不透明物体画面"当作背景，按视差/法线做一个 UV 偏移采样**，模拟光路弯曲。

### 3.2 URP 实现要点
1. URP Asset 中开启 **Opaque Texture**（Camera Opaque Texture）→ 管线每帧生成 `_CameraOpaqueTexture`。
2. Shader（Transparent 队列）中：
   ```
   float2 uv = screenPos.xy / screenPos.w;          // 本片元屏幕 UV
   float3 V = -WorldSpaceViewDir;                    // 视线方向
   float3 R = refract(-V, N, eta); 或简化 N 偏移;
   float2 offset = R .xy / R.z * k;                  // 偏移量（k 折射强度）
   float4 col = tex2D(_CameraOpaqueTexture, uv + offset);
   ```
3. 偏移尺度**乘深度差**（见 §4）后作为折射结果，与水体自身颜色、反射按菲涅尔混合。

### 3.3 局限
- 屏幕边缘/被前景遮挡处无背景可采 → 用深度保护钳制（§4）。
- `_CameraOpaqueTexture` 分辨率 = 屏幕分辨率，带宽成本高；性能优化可在低分辨率 RT + 双线性。

## 4. 折射深度保护（Refraction Depth Protection）

### 4.1 问题
裸的 UV 偏移在三种情况会**穿帮**：
- ① 水下物体贴近水面（偏移把它"掰弯"到奇怪位置）；
- ② 掠射角（视线几乎平行水面）下偏移被放大；
- ③ 浅水区（水面本身离背景近），任何偏移都是错的。

### 4.2 三件套
```
1) 深度差因子：
   float sceneDepth = LinearEyeDepth(_CameraDepthTexture, uv_未偏移);
   float waterDepth = LinearEyeDepth(screenPos.w 处水面深度);
   float depthDiff  = sceneDepth - waterDepth;           // 背后物体距离水面的"空间深度"
   float depthBlend = 1 - exp(-depthDiff * _DepthSharp); // 深水=1，浅水→0
2) 菲涅尔因子：
   float fresnel = pow(1 - saturate(dot(V, N)), _FresnelPow);
   float offBlend = depthBlend * (1 - fresnel * 0.6);    // 掠射角收敛
3) UV 偏移上限：
   offset = clamp(offset, -max, +max);                   // 绝对保险闸
```
最终：`uv' = uv + offset * offBlend`。
高规格实现（HZD/影视向）还会用**深度方向重投影校验**（back-projection check）去掉"错了还硬采"的像素——本项目用第 1、2、3 条即达到目标。

## 5. 动态水体交互（Dynamic Water Interaction）

### 5.1 目标效果
人物/物体入水 → 落点产生涟漪与浪花，水面"感知"到对象。视频里荷花、角色走动带起的波纹属于此类。

### 5.2 交互纹理方案（本项目采用）
把"交互信息"**画进一张正交投影的 RenderTexture**，Shader 每帧采样：

1. **RT 定义**：如 256×256，覆盖相机周围 N×N 米（如 20×20m），MoveWithCamera。
2. **写入侧**（交互发生器脚本）：
   - 每帧 `Graphics.Blit(clear)`（或 ClearRenderTarget 至 0.5 灰 = 无交互）。
   - 对每个交互点（入水点/移动物体）：在 RT 的对应 UV（世界坐标 → RT 的逆正交矩阵）处，
     `GL.Quad`/sprite 画一个**径向渐变圆**：RGB=法线方向扰动，A=强度；随时间扩散（圆半径 = f(t)）。
3. **读取侧**（水体 Shader）：
   - 把片元/顶点世界坐标 → 交互 RT 的 UV（用与写入端同一套正交矩阵，脚本传入 `_InteractionMatrix`）。
   - 采样 → 得到该点交互强度/扰动 → 加进格斯特纳幅值（几何）与法线（光照）。

### 5.3 交互源（逻辑层脚本职责）
- `WaterInteractionEmitter`（逻辑层）：监测物体速度/入水深度 → 生成 InteractionEvent（数据层 struct）。
- 交互事件包含：位置、半径、强度、寿命、衰减曲线。

### 5.4 HZD 的更高做法（记录不实现）
交错网格水模拟（区域流体近似）、屏幕空间交互变形；对性能要求高且超出本项目范围。

## 6. RNW 法线混合（RNW Normal Blending）

### 6.1 术语说明（重要）
"RNW 法线混合"是视频作者在简介中使用的名称，**未检索到公开权威定义**。
水圈通行的等价技术是：**将"解析波法线"与"细节法线"按波长/距离加权混合，重建法线使高低频无缝衔接**。
本项目按此通行方案实现，并在文档中如实标注（不含推测性包装）。

### 6.2 为什么要混
- 长波（§1 主浪）：决定水面宏观起伏——解析法线精确。
- 短波（细节）：决定高光闪烁与小波纹——用细节法线（贴图流动或程序噪声）。
- 只留长波 → 水面"塑料"；只留细节 → 没有形状。

### 6.3 混合方案
```
// 解析法线（§1.3）
float3 nAnalytic = GerstnerNormal(worldPos, time);
// 细节法线（双 UV 流动采样，或程序 ripple 法线 §7）
float3 nDetail   = UnpackNormal(tex2D(_DetailNormalMap, uv*flow));
// 距离/波长权重：远处只看形状，近处加细节
float w = saturate(distance(worldPos, cameraPos) * _DetailStartRcp);
float3 N = normalize(lerp(nAnalytic, nDetail, w));

// 可选：交互扰动（§5）用"重建法线"方式叠加：
//   N = normalize(N + interactionNormal * interactionStrength);
```
高光质量要点：
- 混合后**必须 renormalize**。
- Smoothness 建议近处高（水清、高光锐）、远处低。
- 细节法线用 **两个 UV 方向流动相加** 或 flowmap，避免"贴图走样/方向感"。

### 6.4 进阶（记录可选）
HZD 系做法：法线由多维波各自贡献"频带"，按频带在屏幕空间的误差加权（screen-space LOD of waves）。
尺度更严谨，但工程量翻倍——本项目用 §6.3 的简化版已能达到视频观感。

## 7. 程序化 Ripple（Procedural Ripple）

### 7.1 原理（无贴图涟漪）
以交互点/随机点为圆心产生的**径向衰减正弦环**：

```
ripple(r, t) = Σ_源  A · sin(k·r − ω·t)· exp(−r·d) · 时间包络
```

- r = 到源的距离；k = 环数密度；ω = 扩散速度；d = 随距离衰减；时间包络 = 从出生到消亡的淡入淡出。
- 低频给顶点（轻微位移），高频给法线（闪烁反光）。

### 7.2 与格斯特纳的区分
- 格斯特纳 = 全场大尺度波浪（周期长、空间大）。
- ripple = 局部小涟漪（周期短、范围小、很快衰减）。
两者**叠加在同一高度场**上：`height = gerstner + ripple*强度`。

### 7.3 Unity 落点
- 顶点/Domain：`offset.y += ripple * amp`；法线乘 `1 + ripple*scale` 再 normalize。
- 若需"雨滴/随机源"：逻辑层生成 N 个随机源，按时间老化（池化），源头全在交互 RT 或常量数组传入 shader。

## 8. 格斯特纳波驱动的浪尖效果（Crest / Foam）

### 8.1 判据：压缩度（GPU Gems 原创量）
格斯特纳波把波面"挤"到浪尖：网格在浪尖处被压缩（面积变小）。定义

```
J = |偏导(dP/dx) × 偏导(dP/dz)|   （变形后面积 / 原面积）
```
当 J → 0（塌缩/压缩）就是浪尖，J > 1 是波谷拉开。泡沫掩码：

```
float foamCrest = saturate((_CrestThreshold − J) / _CrestSoftness);
```

### 8.2 三个泡沫叠加
| 来源 | 判据 | 用途 |
| ---- | ---- | ---- |
| 浪尖泡沫 | J 小（§8.1） | 主浪白沫、浪尖卷曲增亮 |
| 岸边浅水泡沫 | 深度差小（§4.1 的 depthDiff） | 岸边拍岸白边 |
| 交互泡沫 | 交互 RT 强度大（§5） | 入水溅起白花 |

`foam = saturate(foamCrest + shoreFoam + interactFoam)` 后：
- 颜色：lerp(水色, 白/乳白, foam)，并加轻微 emissive；
- 高度：泡沫处顶点略抬高（`+ foam * _FoamLift`）让白沫"骑"在浪尖上；
- 浪尖卷曲本身由格斯特纳水平位移产生（Q 大时自然卷）。

### 8.3 动画一致性
判断 J 需要在**同一次位移函数调用**里复算偏导；把 "Gerstner(x,z) → (位移, J, 法线)" 包成一个 HLSL 函数，顶点与片段各调用一次（顶点只取位移，片段取 J/法线/泡沫）。
