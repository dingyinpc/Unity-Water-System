## 🟢 零基础导读（先看这一节）

**这个项目在干什么？**
一个抖音博主做了一段"Unity 水体 shader"的视频（海面、浪花、倒影、昼夜天空）。我们的目标是**照着它把同样的效果在自己电脑上做出来**，并且把"怎么做的"写成你能看懂的文档。你不需要懂编程——文档里凡是出现术语，我都会用一句大白话解释。

**这次工作的方法（三步循环，每一步都留证据）**
1. **看原视频**：把视频**每一帧**都拆出来（一共 5568 张图），一帧一帧看它在做什么；
2. **动手做**：在我们的工程里写代码，做出同样的效果；
3. **对答案**：把"我们做出来的画面"和"视频里的画面"用数字比一比（比如颜色值、亮暗、比例），差在哪就写清楚，再回去改。

每一步都会产出一份 **《检测报告》**（`Docs/学习路径与知识库/检测报告/Rxx_*.md`），里面有：看了哪些帧、量到了什么数、我们做了什么、差多少、还差什么。

**文档怎么看**

| 文档 | 一句话说明 |
| --- | --- |
| `08_参考视频知识点全解.md` | 视频里到底讲了什么（15 章内容全文转录） |
| **`09_...补齐路线.md`（本文）** | 总路线：我们缺什么、先补哪个、每步状态 |
| `检测报告/R01_…` | 第 1 步（近岸水流）的详细报告 |
| `检测报告/R02_…` | 第 2 步（水面倒影 SSR）的详细报告 |
| `01`~`07` | 之前的理论/教程/踩坑记录 |

**术语小词典（遇到看不懂的回来查）**

| 词 | 大白话 |
| --- | --- |
| **shader（着色器）** | 一段"决定每个像素长什么样"的小程序 |
| **水体渲染** | 让一摊水看起来像水（会反光、会透、会起浪） |
| **帧 / 逐帧** | 视频一秒 30 张图，一张叫一帧；逐帧=每张都看 |
| **Gerstner 波** | 一种用数学公式直接算出"浪的形状"的方法 |
| **FFT** | 另一种更高级的造浪方法（用频率拼出真实海面），我们还没做 |
| **细分（Tessellation）** | 把一块平面切成更多小格子，浪才画得细 |
| **SSR（屏幕空间反射）** | 让水面映出岸上的东西（相机里能看见什么，就映什么） |
| **菲涅尔** | 正着看水是透明的、斜着看水像镜子 |
| **Beer-Lambert** | 光在水里越走越暗的规律 |
| **Macro/MAC 网格** | 把水面切成小格子，每个格子记"水位"和"水流速度" |
| **调试图** | 把"程序里的数字"直接画成颜色（蓝=有水、橙=没水），用来判断程序对不对 |
| **A/B 对比** | 同一画面"开关某个效果"各截一张，做差看它到底有没有起作用 |
| **commit** | 代码的"存档点"，能随时回溯 |

## 3. 标准检测报告模板（每一步都照此产出）

每份报告落 `Docs/学习路径与知识库/检测报告/Rxx_*.md`，固定六节：

```markdown
# Rxx · <步骤名> 检测报告

## 0 元信息
日期 / 参考时间码区间 / 目标场景 / 涉及文件 / commit / Unity 版本+管线

## 1 参考侧逐帧量测（参考）
- 量测方法（工具 + 命令，可复现）
- 数据表（每帧/分段统计：白沫占比、色相分桶、亮度、运动能量…）
- 关键帧图注（帧号 @ 秒 → 画面内容）
- 结论（参考在该章"做了什么、什么参数级别"）

## 2 我方现状量测（现状）
- 现有实现（文件/菜单/shader 行）
- 现有截图/探针数据；标注数据来源（Play 截图 / 探针 log / 离线）
- 局限说明（哪些没测到、为什么）

## 3 差距对比
- 数值对照表（同口径：色相/亮度/占比…）
- 定性差距清单（逐条）

## 4 补齐实施
- 方案（论文/出处 + 落点）
- 新增/修改文件清单
- 可复现命令（菜单号 / 桥命令）

## 5 验收判据与结果
- 判据（可量化：数值阈值 or 帧级特征）
- 回归结果（真机验收前标 `待 Unity`）

## 6 遗留与风险
```

## 4. 执行纪律（沿用本项目既有教训）

1. **先量后调**：任何参数改动前先量参考帧（`Tools/sample_png.ps1` / 逐帧 `metrics.csv`），不靠眼估。
2. **真机验收**：Unity 侧结论必须来自 Play 模式真实 Game 截图或探针 log；离线图不算验收（《05》★G-18）。
3. **唯一真源**：每个参数只在一个菜单里写（《05》根因 11），别在 `.mat` 与菜单各写一份。
4. **入库存结论，不入库存素材**：原片/frames 全部 gitignored，只有文档与本路线入库。
5. **小步提交**：每完成一个 Px 步骤本地提交（大版本才推 GitHub）。
