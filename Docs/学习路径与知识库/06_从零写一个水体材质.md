# 从零写一个水体材质（06）—— 教你自己把它做出来

> 这份文档**不是**"按哪个菜单"，也**不是**"八项技术分别是什么"（那是《01》）。
> 它是：**打开一个空的 shader 文件，一级一级往上搭，每一级都能看到水面变得更像一点。**
> 每级都给：**要解决的问题 → 可以直接敲的代码 → 你会看到什么 → 敲错了会长什么样 → 为什么**。
> 走完 10 级，你手里就是本项目那个水面；第 10 级（平面反射）做完，它才真的像"一潭水"而不像"一块水纹材质"。

---

## 先建立心智模型：水面到底在算什么

**一个水面像素的颜色，只来自三个地方：**

```
        ┌─── 水【上面】的空气 ───┐
        │   天空 / 太阳 / 云      │  → 反射进来（掠射角越多，反射越强）
        └──────────┬─────────────┘
      ～～～～～～～ 水面 ～～～～～～～   ← 法线决定"往哪看"和"反射谁"
        ┌──────────┴─────────────┐
        │   水【下面】的东西      │  → 折射进来（被法线折弯），并随深度被吸收
        │   沙底 / 石头 / 深水    │
        └────────────────────────┘

   再往"表面"上叠两样：  高光（太阳的镜面反射）  +  泡沫（白）
```

所以整个 shader 就是这四句话：

| 成分 | 代码里的形状 | 决定它的是什么 |
| ---- | ------------ | -------------- |
| ① 底下 | `lerp(col, 屏幕色, 权重)` | 水深、菲涅尔 |
| ② 上面 | `col += skyCol * fres` | 菲涅尔、天空渐变 |
| ③ 高光 | `col = lerp(col, 太阳色, spec)` | 法线 vs 半角向量 |
| ④ 泡沫 | `col = lerp(col, 泡沫色, foam)` | 浪尖压缩度、到岸距离 |

而**这四样全部依赖同一个东西：水面法线 `N`**。
法线错，①②③ 全错 —— 这就是为什么本项目一半的难度都花在"怎么把法线算对"上（第 2 级和第 6 级）。

> **一句话记住**：水面不是"一种颜色"，是**"一个会折弯光线的透明界面"**。你的工作只有两件：① 把界面形状算出来（几何+法线）；② 按这个形状去问"这里该看哪里"。

## 第 0 级：先让一块透明色出现

**目的**：不是做水，是**确认管线通**。透明、深度纹理、抓屏这三样在 URP 里都要手动开，不开的话后面每一级你都会以为是自己的代码错了。

### 0.1 工程设置（漏了后面全白搭）

`Edit → Project Settings → Graphics` → Scriptable Render Pipeline Settings 指向你的 URP Asset。

打开 URP Asset，**这两项必须勾**：

| 选项 | 干什么用 | 不勾的症状 |
| ---- | -------- | ---------- |
| **Depth Texture** | 算"这里水有多深" | 水面永远一个颜色，浅滩深水没区别 |
| **Opaque Texture** | 抓"水面下面的画面" | 折射采样拿到全黑或垃圾数据 |

### 0.2 最小 shader

```hlsl
Shader "Learn/Water"
{
    Properties { _Color("颜色", Color) = (0.1, 0.4, 0.45, 0.8) }
    SubShader
    {
        Tags { "RenderType"="Transparent" "Queue"="Transparent" }
        Pass
        {
            Tags { "LightMode"="UniversalForward" }
            Blend SrcAlpha OneMinusSrcAlpha   // 半透明混合
            ZWrite Off                        // ⚠ 必须关，否则挡住水底
            Cull Off

            HLSLPROGRAM
            #pragma vertex vert
            #pragma fragment frag
            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"

            float4 _Color;
            struct A { float4 pos : POSITION; };
            struct V { float4 pos : SV_POSITION; };

            V vert(A v) { V o; o.pos = TransformObjectToHClip(v.pos.xyz); return o; }
            half4 frag(V i) : SV_Target { return _Color; }
            ENDHLSL
        }
    }
}
```

建一个材质用它，贴到一块比池塘大的平面上，摆在 y=0。

**你会看到**：一块半透明的青绿色平板。

**做错了会怎样**：
- **纯白/纯灰** → `LightMode` 标签写错或没 include `Core.hlsl`
- **完全不透明** → `Blend` 没写对，或 `Queue` 不是 `Transparent`
- **水底下的东西全消失** → `ZWrite` 没关

> ⚠ **水面和地面不要共面**。地面顶面 y=0、水面也 y=0 → z-fighting，从陡角度会看到地面"吃掉"水面。**把水面上浮 2cm（y=0.02）**。这是本项目真实踩过的坑。

**这一级过关标准**：能透过水面清楚看到底下的地面。

## 第 1 级：让水动起来 —— Gerstner 波与它的解析法线

**目的**：水面要有起伏。**但真正重要的不是顶点位移，是法线** —— 观众看到的"波浪感" 90% 来自法线，不是几何。

### 1.1 为什么不用"正弦波抬高度"

正弦波只上下动，水面**水平方向不挤**，所以波峰波谷的斜面看起来一样宽 → 像一张起伏的桌布，不像水。

Gerstner 波的洞见是：**水粒子其实走的是圆**。

```
x = x₀ − Q·A·dx·cos(phase)      ← 水平方向也移动！
y =      A·sin(phase)            ← 垂直
z = z₀ − Q·A·dz·cos(phase)
phase = dot(xz, d)·ω + phase₀ − t·ω·speed
```

- `A` 振幅、`ω` 频率（越小波长越长）、`d` 传播方向、`Q` 陡度
- `Q=0` 退化成纯正弦；`Q` 越大波峰越尖
- **约束 `Σ Q·ω·A < 1`**，超过就会"卷浪自交"（面翻过来）

### 1.2 法线必须解析求导，不能用 `CalculateNormal`

把上面的式子对 x₀、z₀ 求偏导，得到切线 T 和副切线 B，叉乘就是法线。**这一步是波浪好不好看的分水岭。**

```hlsl
// 累加每条波的偏导量
float dPxdx = 1, dPxdz = 0, dPzdx = 0, dPzdz = 1, dPydx = 0, dPydz = 0;

float wcx = w * c;                                  // w·cos(phase)
dPxdx -= Q*A*d.x*d.x*wcx;      dPxdz -= Q*A*d.x*d.y*wcx;
dPzdx -= Q*A*d.y*d.x*wcx;      dPzdz -= Q*A*d.y*d.y*wcx;
dPydx += A*d.x*wcx;            dPydz += A*d.y*wcx;
// （P.x/P.z/P.y 的位移同时累加）

float3 T = float3(dPxdx, dPydx, dPzdx);
float3 B = float3(dPxdz, dPydz, dPzdz);
float3 N = normalize(cross(B, T));
```

### 1.3 顺手白送一个宝贝：压缩度 J

```hlsl
float J = dPxdx * dPzdz - dPxdz * dPzdx;   // 水平面积变化率
```

`J = 1` 平静，`J < 1` 水平被压缩 = **波峰**。这就是第 7 级浪尖泡沫的判据，**不用额外算任何东西**。

### 1.4 把它接到管线上

本项目在 **domain shader** 里做位移（因为第 8 级要细分）。第 1 级你可以先放在顶点着色器：

```hlsl
// 顶点：先转世界，位移，再转回裁剪空间
float3 worldPos = TransformObjectToWorld(v.pos.xyz);
GerstnerResult gr = GerstnerEval(worldPos, _Time.y);
o.pos      = TransformWorldToHClip(gr.pos);
o.worldPos = gr.pos;
o.normal   = gr.normal;      // 传给片元
```

**你会看到**：水面开始起伏，**而且光照会有明暗流动**（因为法线对了）。

**做错了会怎样**：
| 症状 | 原因 |
| ---- | ---- |
| 起伏了但像塑料/桌布 | 法线还是原来的 `(0,1,0)`，没解析求导 |
| 水面翻面、出现破洞 | `Σ Q·ω·A ≥ 1`，卷浪自交了 |
| 波浪整片整齐重复 | 只有 1–2 条波，或频率成整数比 |
| 波不动 | `_Time.y` 没传进来，或 `phase` 里没有 `- t*...` |

### 1.5 让它"不像程序"：多波 + 互不调和 + 幅值调制

单条波一定假。本项目用 **6 条**，频率/方向/相位**互不成整数比**，再加一个跨池的低频幅值调制：

```hlsl
// 让波浪在空间上忽强忽弱（约 57m / 34m 两种波长叠加），并随时间缓慢漂移
float phaseM = dot(worldPos.xz * 0.11, float2(0.7, 0.3)) + t * 0.11;
float ampMod = 0.72 + 0.28 * (sin(phaseM) * 0.6 + sin(phaseM * 1.7 + 2.1) * 0.4);
A *= _WaveAmpScale * ampMod;

// 每条波相位速度再 ±10% 漂移，让波族互相滑动
float speed = _WaveTimeScale * (1.0 + 0.10 * sin(phase0 * 7.0 + t * 0.05));
```

> **过关标准**：盯着水面看 10 秒，找不到重复周期。

## 第 2 级：让水有"深度" —— 从场景深度纹理算真实水深

**目的**：浅滩浅蓝、深水墨绿。这是"是水不是玻璃"的第一线索。

### 2.1 取深度

```hlsl
#include ".../ShaderLibrary/DeclareDepthTexture.hlsl"

// ⚠ 关键：屏幕空间 UV 必须用【自己传的裁剪坐标】算，不能蹭 SV_POSITION
float4 sp = IN.clipPos * 0.5;
sp.xy = float2(sp.x, sp.y * _ProjectionParams.x) + sp.w;
float2 screenUV = sp.xy / sp.w;

float sceneDepth = LinearEyeDepth(SampleSceneDepth(screenUV), _ZBufferParams);
float waterDepth = IN.clipPos.w;              // 水面自己的视深
float gap = max(sceneDepth - waterDepth, 0.0);  // 这段距离里都是水
```

> ### ⚠ 本教程最重要的一条警告
> **`SV_Position` 在片元阶段是像素坐标（0..1920），不是裁剪空间坐标。**
> 如果你在结构体里只写 `float4 pos : SV_POSITION` 然后拿它算 `screenUV`，你会得到一个巨大的数，采样到的是画面角落的垃圾值 —— 而且**水面不会报错、不会变黑，只会"发奶白、怎么调都不透"**。
>
> 本项目这个 bug 让开发卡了**好几个小时**，并且基于它产出的"诊断数据"得出过一连串错误结论。
>
> **正确做法**：结构体里**另外带一份裁剪坐标**：
> ```hlsl
> struct V {
>     float4 positionCS : SV_POSITION;   // 光栅化用
>     float4 clipPos    : TEXCOORD3;     // 屏幕空间采样用这个
>     ...
> };
> ```

### 2.2 按深度混合深浅色（Beer–Lambert）

```hlsl
float depthMix = 1.0 - exp(-gap * _Absorb);          // 0=浅, 1=深
float3 waterBase = lerp(_ShallowColor, _DeepColor, depthMix);
float3 col = waterBase * (ambient * _AmbientStrength + mainLight.color * ndl);
```

### 2.3 ⚠ `gap` 是**视深**，不是垂直水深

`sceneDepth` 和 `waterDepth` 都是 `LinearEyeDepth`，所以 **`gap` 是"沿视线走了多少米"**。

低机位视线接近水平时，**1m 的垂直水深会被算成约 4m 视深**。后果：

- 一个只有 1.3m 深的池子，`_Absorb = 1.9` → 全池 `depthMix ≈ 0.92` → **整池都被判定成深水**，连浅滩也是深色，而且**近岸比塘心还暗**（和真实水面完全相反）。
- 本项目把 `_Absorb` 降到 **0.85** 才正常。

> **教训**：吸收系数没有"通用值"，**必须按你这个水池的实际深度标定**。换个场景尺寸就得重调。
> 任何"按水深"的效果（颜色、泡沫带）都要先问自己：我用的是垂直水深还是视深？

**你会看到**：中间深、边上浅，水面开始有"厚度感"。

**做错了会怎样**：
- 全池一个颜色 → `gap` 恒为 0（多半是上面那个 `SV_Position` 坑，或 Depth Texture 没开）
- 浅滩比深水还暗 → `_Absorb` 太大 / 用了视深
- 水面边缘出现一圈"错位的地面" → 折射还没做（第 3 级），正常

## 第 3 级：让人看穿水底 —— 屏幕空间折射

**目的**：真正的透明不是"调低 alpha"，而是**把底下的画面按法线折弯后搬上来**。

### 3.1 用 Snell 定律算折弯方向

```hlsl
#include ".../ShaderLibrary/DeclareOpaqueTexture.hlsl"

float3 refr = refract(-V, N, _Eta);          // 空气→水，IOR 1.0/1.33
if (dot(refr, refr) < 1e-5) refr = -V;       // 全反射兜底（否则会 NaN）
float2 refrDir = normalize(refr.xy + 1e-6);
```

### 3.2 偏移 UV 去抓屏

```hlsl
float2 uvOff = refrDir * _RefractStrength * (0.5 / max(abs(refr.z), 0.05));
uvOff = clamp(uvOff, -_MaxUVOffset, _MaxUVOffset);   // ⚠ 上限必须有

float depthBlend = 1.0 - exp(-gap * _DepthSharp);    // 深水才折射（浅水直接看底）
float2 refrUV = screenUV + uvOff * depthBlend * (1.0 - fres * 0.75);

float3 refrCol = SampleSceneColor(refrUV);
col = lerp(col, refrCol, (1.0 - fres) * (1.0 - depthMix) * 0.58);
```

### 3.3 三个必须同时存在的保护

| 保护 | 代码 | 少了会怎样 |
| ---- | ---- | ---------- |
| **深度保护** | `depthBlend` | 岸边水很浅也大幅折弯 → 湖底纹理被拉飞 |
| **菲涅尔收敛** | `* (1 - fres*0.75)` | 掠射角本该反射为主，却还在折射 → 远处水面"穿帮" |
| **偏移上限** | `clamp(..., _MaxUVOffset)` | 位移无限大 → 整片糊成一团 |

> ⚠ **`_MaxUVOffset` 是个极敏感参数**，它是**屏幕比例**。0.12 在 906px 高下能偏 108px —— 把任何折射都抹成糊。本项目从 0.12 降到 **0.025** 才有"透彻感"。

**你会看到**：能看见水底的沙纹和石头，而且它们的位置随波浪轻微晃动 —— **这才是"水"而不是"蓝色玻璃"**。

**过关标准**：把相机拉近，能认出湖底的鹅卵石轮廓。

## 第 4 级：让水反射天空 —— 菲涅尔

**目的**：低头看水里（看见底），抬头方向看水面（看见天）。这是水面最有说服力的一条线索。

```hlsl
// 菲涅尔：视线越"掠"过水面，反射越强
float fres = pow(1.0 - saturate(dot(V, N)), _FresnelPow);

// 反射方向决定"看到天上哪一块"
float3 reflDir = reflect(-V, N);
float3 skyCol = lerp(_SkyHorizon, _SkyZenith, saturate(reflDir.y));

col += skyCol * fres * _SkyReflect;
```

### ⚠ 两个坑

**坑 1：反射方向的天空映射别写错**

`reflDir.y` 是"反射看向多高的天空"。
- 掠射（远处水面）→ `reflDir.y ≈ 0` → **应该取地平线色（亮）**
- 低头看脚边 → `reflDir.y ≈ 1` → 取天顶色（暗）

如果写成 `reflDir.y * 0.5 + 0.5`，掠射会被映射到 `0.5` 偏暗的位置 → **低机位下大半水面发黑发闷**。本项目就是这么错的。

**坑 2：`_FresnelPow` 决定"有多少水面在照镜子"**

`pow(1 - dot(V,N), n)`，`n=6` 时俯角 10° 的水面 `fres` 才 **0.33**，必须贴着地平线才趋近 1。
→ **画面里绝大部分水面根本没在反射**，你再怎么加亮天空反射都没用。

本项目降到 **`_FresnelPow = 4`**（配合 `_SkyReflect = 1.0`）才出现成片的高亮反射场。

> **这是第 6 级"碎闪"的关键伏笔，先记住。**

**你会看到**：远处水面变成一面偏亮的镜子，近处能看穿到底 —— **水立刻"活"了**。

## 第 5 级：太阳的高光 —— 两种不同的镜面反射

水面上的"亮"其实是**两个不同的东西**，必须分开写：

```hlsl
// ① Blinn-Phong 高光：锐利的白点，跟着视角走
float3 H = normalize(mainLight.direction + V);
float spec = saturate(pow(saturate(dot(N, H)), _SpecPower) * _SpecStrength);
col = lerp(col, _SunColor.rgb, spec);          // ⚠ lerp，不是 +=

// ② 太阳反光带：反射方向对准太阳时整片变亮
skyCol += _SunColor * pow(saturate(dot(reflDir, mainLight.direction)), _SunGloss) * _SunStrength;
```

### ⚠⚠ 高光必须用 `lerp`，不能用 `+=`

```hlsl
col += _SunColor * spec;   // ❌ 无界累加
```

本来就不亮的水色被顶过 1.0 → ACES 把它**削平成一片死白**。这就是本项目"水面突然出现大片突兀白斑"的真因。
`lerp(col, _SunColor, spec)` 的上界就是太阳色本身，**永远不会过曝**。

### ⚠ "碎闪是几何条件，不是强度旋钮"

`_SunGloss` 控制太阳反光带**有多聚**。`pow(cos δ, n)` 的半高宽约 `1.3/n` 弧度：

| `_SunGloss` | 半高宽 | 在 52° 视场里占画面高度 | 看起来 |
| ----------- | ------ | ---------------------- | ------ |
| 1500 | ±0.5° | 1% | 几乎没有 |
| **700** | **±1.8°** | **4%** | **一条细线** |
| 90 | ±14° | ~30% | **一整片高光场** ✅ |

本项目为了"碎闪成片"，把 `_SunGloss` 从 700 降到 **90**，同时因为覆盖面积涨了约 8 倍，把 `_SunStrength` **从 3.4 降回 2.2**（否则整幅洗白）。

> **元教训**：觉得"高光不够亮"时，**先算它在画面那个几何条件下能取到多大面积**。再大的强度乘在 4% 覆盖率上也只是一条线。

**你会看到**：水面偏一侧出现一条波光粼粼的亮带，转头/转相机它会跟着移动。

## 第 6 级：让水面有"质感" —— 细节法线与距离混合

**目的**：Gerstner 波只有 6 条，是**大形状**。真实水面在近处还有密密麻麻的小涟漪。这些**不该用几何做**（太贵），应该用法线做。

### 6.1 用噪声的梯度当法线扰动

```hlsl
// 值噪声（Perlin 插值本体），梯度用前向差分算
float2 NoiseSlope(float2 worldXZ, float scale, float2 flow)
{
    float2 q = worldXZ * scale + flow;
    const float eps = 0.25;
    float n0 = ValueNoise(q);
    float nx = ValueNoise(q + float2(eps, 0.0));
    float nz = ValueNoise(q + float2(0.0, eps));
    return float2(nx - n0, nz - n0) / eps;
}

float3 DetailNormal(float3 worldPos, float t)
{
    // 三层八度：大波 + 中波 + 高频小波，各自反向流动 → 多向流动感
    float2 total = NoiseSlope(worldPos.xz, _DetailScale,        float2( t*0.42,  t*0.33)) * 0.40
                 + NoiseSlope(worldPos.xz, _DetailScale * 2.1f, float2(-t*0.33, -t*0.42)) * 0.55
                 + NoiseSlope(worldPos.xz, _DetailScale * 5.4f, float2( t*0.55, -t*0.47)) * 0.50;
    return normalize(float3(-total.x * _DetailStrength, 1.0, -total.y * _DetailStrength));
}
```

### 6.2 ⚠ 梯度必须用差分，不能用解析导数

本项目最初用解析梯度，结果**水面出现规则棋盘格** —— 因为值噪声在格边界上解析导数**归零**，每个格子变成一个朝向的平面。
改用**前向差分**后梯度跨格连续，棋盘格消失。

> **"看起来像网格"不一定是网格拓扑问题**，先查函数连续性。

### 6.3 按距离混合（远处不要细节，会闪）

```hlsl
float distCam = distance(worldPos, _WorldSpaceCameraPos);
float detailW = saturate((distCam - _DetailStart) / max(_DetailEnd - _DetailStart, 1e-4));
N = normalize(lerp(N, nDetail, detailW));      // 近处偏细节，远处偏 Gerstner
```

### 6.4 三层八度的权重分配是"碎闪"的另一半

第 5 级说 `_SunGloss` 决定反光带多宽。但**光有宽波瓣只会得到"一大片均匀的亮"** —— 要"粼粼"，必须有足够多、足够小的朝向变化。

本项目最初只有低频两层，导致"整块面元一起亮"→ 死白。把低频权重从 0.70 降到 0.40、能量挪给两层高频，并把 `_DetailScale` 提到 **7.6**，碎闪才变成**密集小点**。

> **元教训**：**"波瓣宽 = 光斑大"这个结论只在法线低频时成立。** 法线足够密时，放宽波瓣只会让点变多变亮。上一轮的"正确参数"可能是这一轮的瓶颈 —— 两个必须成对考虑。

**你会看到**：水面从"光滑的果冻"变成"有皮肤"，近处密密麻麻的小闪光。

## 第 7 级：泡沫 —— 三个来源

泡沫让水"物理上可信"。三个独立来源，都要：

```hlsl
// ① 浪尖：直接用第 1 级白送的压缩度 J
float crestFoam = saturate((_CrestJ - gr.J) / max(_CrestSoft, 1e-4));

// ② 岸边：⚠ 必须换算回【垂直】水深！
float vd = gap * max(V.y, 0.12);
float shoreFoam = saturate((1.0 - vd * 1.7) * (1.0 - fres) * 0.75);

// ③ 交互（点击/物体入水，来自一张 RT）
float interFoam = interA * _InteractionFoam;

float foam = saturate(crestFoam * _CrestFoam + shoreFoam * _ShoreFoam + interFoam);
float3 foamCol = _FoamColor * (1.0 + crestFoam * 0.5);
col = lerp(col, foamCol, foam);
```

### ⚠ 岸边泡沫那个 `vd` 是本教程第二个"视深"陷阱

`gap` 是视深。低机位下 1m 垂直水深被读成 ~4m 视深 → **泡沫带宽被压到约 17cm，画面上完全看不见**。
本项目一开始想用"到最近石头的水平距离"来绕开，那是治标。真正的修法就一行：

```hlsl
float vd = gap * max(V.y, 0.12);   // V.y 是视线向上的分量 → 视深 × sin(俯角) ≈ 垂直水深
```

**泡沫带宽从此与观察角度无关。**

### 交互泡沫要收敛

`col + _FoamColor * interFoam * 0.12` —— 那个 `0.12` 很关键。本项目最初是 0.4，结果**水面莫名冒出白色大圈**（演示模式每 0.45s 随机砸一次涟漪）。

**你会看到**：波峰有白沫、水线有一圈白边、点击水面有涟漪白环。

## 第 8 级：曲面细分 —— 让近处几何够密

**目的**：水面网格如果固定 100×100，近处会看到明显的折面，远处又浪费三角形。DX11 曲面细分可以**近密远疏**。

```hlsl
#pragma hull hull
#pragma domain domain
```

### 8.1 关键：按"目标世界尺寸"算因子，不是按固定倍率

```hlsl
float TessFactorForEdge(float3 a, float3 b, float3 cam)
{
    float d = distance((a + b) * 0.5, cam);
    float k = saturate((d - _TessNear) / max(_TessFar - _TessNear, 1e-4));  // 距离衰减
    float sizeFactor = distance(a, b) / max(_TessTargetSize, 1e-4);         // ⚠ 基边长/目标尺寸
    float f = sizeFactor * (1.0 - k);
    return max(1.0, ceil(min(f, _MaxTess)));
}
```

> ⚠ **不要用固定 `_MaxTess`**。本项目最初 `_MaxTess=12` 套在 40m 池塘（基边 0.42m）上 → 细分到 3.5cm 微型三角形 → **百万级面，FPS 崩到 1.7**。
> 改成按目标尺寸自适应后，**任何网格分辨率都收敛到同样的三角形密度**。

### 8.2 Hull / Domain 骨架

```hlsl
[domain("tri")]
[partitioning("fractional_odd")]
[outputtopology("triangle_cw")]
[patchconstantfunc("hullConstant")]
[outputcontrolpoints(3)]
[maxtessfactor(64.0)]
TessControlPoint hull(InputPatch<TessControlPoint,3> patch, uint id : SV_OutputControlPointID)
{ return patch[id]; }

[domain("tri")]
WaterVaryings domain(TessFactors factors, const OutputPatch<TessControlPoint,3> patch, float3 bary : SV_DomainLocation)
{
    float3 positionOS = patch[0].positionOS*bary.x + patch[1].positionOS*bary.y + patch[2].positionOS*bary.z;
    float3 worldPos = TransformObjectToWorld(positionOS);

    GerstnerResult gr = GerstnerEval(worldPos, _Time.y);   // ← 第 1 级的位移搬到这里
    // ... 交互位移、ripple 位移

    o.positionCS = TransformWorldToHClip(gr.pos);
    o.clipPos    = o.positionCS;      // ⚠ 第 2 级那个坑，必须在这里传出去
    o.worldPos   = gr.pos;
    o.viewDir    = _WorldSpaceCameraPos - gr.pos;
}
```

### 8.3 细分必须在 Gerstner 之前

顺序是 `网格 → 细分出更多点 → 每个点做位移`。反过来（先位移再细分）插值出来的是错的形状。

**你会看到**：贴近水面时波纹足够细腻，FPS 还稳。

> 本项目最终值：`_MaxTess 6 / _TessNear 6 / _TessFar 32 / _TessTargetSize 0.35` → **30–320 FPS**。
> ⚠ **低机位近水平视角会让整池水面都落进细分近距**，这是最容易爆的地方，改机位后务必重测 FPS。

## 第 9 级：让它"好看" —— 这一步不在 shader 里

前 8 级做完，你的水面**技术上全对，但看起来可能还是"不像"**。因为水面的颜色是被**光照 + 后处理**决定的。

本项目最贵的三个坑全在这里：

### 9.1 调参顺序必须是：曝光 → 光源 → 反照率 → 色相

**反例**：岩石/水面近黑，第一反应"反照率太低"，改了三轮没用。

真因是 `postExposure 0.55` 太低 → **中间调整个落进 ACES 曲线的趾部被压平**。这时候调反照率，只会"亮的过曝、暗的还是死"。

```
Volume: ACES + postExposure 1.15 + saturation 14
```

### 9.2 用"受光/阴影比值"判断该调光还是调材质

拿参考帧量两个数：

| 参考帧实测 | 值 |
| ---------- | -- |
| 受光岩石 | `(103,130,154)` |
| 阴影岩石 | `(88,122,151)` |
| **比值** | **仅 1.2 倍** |

→ 说明参考是个**天光主导、几乎平涂**的场景，直射光占比很小。
→ 所以"岩石近黑"**不是反照率问题，是环境光太弱**。

如果你自己的渲染里这个比值是 3–5 倍，去调 ambient，别调材质。

```
RenderSettings.ambientMode = Trilight
sky (0.500,0.580,0.680)  equator (0.440,0.500,0.470)  ground (0.290,0.270,0.230)
```

### 9.3 太阳仰角决定所有朝上面的亮度

本项目为了"碎闪几何"把太阳压到仰角 14° → 朝上面 `N·L = sin14° = 0.24` → **岩石顶、树冠、沙面集体失光**。

> **"很多物体同时暗"通常是光源问题，不是逐个物体的材质问题。找共因。**

### 9.4 颜色值要按"过 ACES 之后"给

| 想要的效果 | 实际该给的值 | 为什么 |
| ---------- | ------------ | ------ |
| 鲜艳的荷花粉 | `0.92,0.56,0.66`（浅粉） | 饱和洋红 `(0.90,0.26,0.50)` 会被 ACES 色相限制**压成砖红** |
| 亮青的水 | 线性值比目测低约 45% | 曝光 1.15 下，目测合适的 sRGB 直接输进线性会过冲 |
| 远景的雾感 | 提亮 + 压饱和 + **偏蓝** | 大气透视 ≠ 变暗；压暗只会得到黑三角 |

> ⚠ 脚本里的 `Material.SetColor` 用的是**线性空间**，截图取的是 sRGB，不能直接抄。

## 第 10 级：让水照出东西 —— 平面反射

> 前 9 级做完，你有一个技术上正确的水面。但它**不照东西**，所以它永远像"贴在地面上的一张水纹贴图"，而不像一潭水。
> 人眼判断"这是水面"的第一线索是**倒影**，不是波浪。

### 10.1 为什么不能用 Reflection Probe

最省事的做法是场景里丢一个探针。对**粗糙的小物体**（石头、金属）探针完全够用。但水面近似的是一块**无限大的水平镜面**：

- 探针是**单点**采样的立方图 → 离探针越远，视差误差越大；
- 岸上的树会倒映在**错误的位置**，而且移动相机时倒影不会正确滑动。

水平镜面必须用**平面反射**：把场景关于水面对称地再渲一遍。URP 14 没有内置，官方文档给的做法就是"自己渲一台子相机到 RenderTexture"。

### 10.2 镜像相机：水平面用欧拉角最省事

关于水平面 `y = waterY` 的镜像极其干净 —— **y 翻折、pitch 取反、roll 取反、yaw 不变**：

```csharp
Vector3 sp = main.transform.position;
Vector3 rp = new Vector3(sp.x, 2f * waterY - sp.y, sp.z);

Vector3 e = main.transform.rotation.eulerAngles;
transform.SetPositionAndRotation(rp, Quaternion.Euler(-e.x, e.y, -e.z));
```

> ⚠ **不要**写成"把 `forward` 和 `up` 的 y 分量各取反，再喂给 `LookRotation`"。
> 反射后的 (right, up, fwd) 三轴组是**左手系**，`LookRotation` 会强行右手化，效果是**同时把 right 和 up 取反** —— 那正是绕视轴滚 180°。
> 症状还不好认：倒影本来就压在水面附近，上下颠倒只表现为"反射带的位置总是差一截"，很容易误判成 UV 算错（本项目就在这上面绕了一大圈，见《05》D-14）。
> 无 roll 时正确写法等价于 `LookRotation(mirrorFwd, Vector3.up)` —— 关键就是**第二参数用世界 up，不是取反后的 up**。

**驱动方式**：镜像相机是一台**正常启用**的相机，`depth = 主相机 - 1`，所以 URP 每帧先渲它，主相机当帧就能用到新 RT。只在 `beginCameraRendering` 里、**且只针对镜像相机自己**更新位姿：

```csharp
void OnBeginCameraRendering(ScriptableRenderContext ctx, Camera source)
{
    if (source != _cam) return;        // ← 少了这个守卫就是无限递归
    var main = Camera.main;
    EnsureRenderTexture(main);
    SetupMirrorCamera(main);
    PublishToWater();
}
```

> ⚠ 不要用 `camera.enabled = false` + 手动 `cam.Render()`。那条路在 URP 下要自己管 renderer 初始化，容易出"渲出来全黑"这种难查的问题。

### 10.3 斜投影：把水面以下裁掉

不做这一步，**池底的泥会被镜像相机当成"水面上方的东西"倒映出来**。做法是把近平面斜切成水面那个平面（"Plane Clipping in 3 Steps"）：

```csharp
static Matrix4x4 ObliqueNear(Matrix4x4 proj, Vector4 clipPlane)
{
    Vector4 q = proj.inverse.MultiplyVector(
        new Vector4(Sgn(clipPlane.x), Sgn(clipPlane.y), 1f, 1f));
    Vector4 v = clipPlane * (2f / Vector4.Dot(q, clipPlane));
    // 列主序：m[2]=m20, m[6]=m21, m[10]=m22, m[14]=m23 —— 即第三行
    proj[2] = v.x - q.x;  proj[6] = v.y - q.y;
    proj[10] = v.z - q.z + 1f;  proj[14] = v.w - q.w;
    return proj;
}
```

两个容易写错的地方：
- **只改第三行**（z 行）。改到第四行会破坏 `w`，之后所有除法都炸。
- 平面是**余向量**，变换要用 `(M_w2c)^{-T}`，即 `c2w^T`。相机在相机空间就是原点，所以它的带符号距离**直接就是 `p.w`**，别把世界坐标再代一遍去判。

> ⚠ **只归一化，不要改符号。** 很多教程写"斜投影要求相机在平面正侧，否则把平面取反" —— 那是 Lengyel 原文的约定（他把裁剪平面当"相机前方的一块墙"来讲），**对镜像相机不成立**：镜像相机本来就在水面**以下**，水面相对它就是它的**近平面**，带符号距离为负是正常状态（任何相机的近平面都在它前面）。
> 顺手加一句 `if (p.w < 0) p = -p;` 的后果是保留的半空间整个反过来 —— 从"保留水面上方"变成"保留水面下方"，于是 RT 采到的正是**池底**。症状是水面上出现一块边界光滑的深色椭圆，把整条对岸倒影盖掉；而因为它形状"看着像岸线"，很容易被误判成阴影或强度问题（《05》D-15）。
> 世界平面给 `(0, 1, -waterY)`（水面上方为正）就一路用到底。

### 10.4 采样：必须传"世界→镜像裁剪空间"矩阵

水材质里**不要**拿自己的 `screenUV` 去采反射 RT —— 那样近处会明显错位。正确做法是把世界坐标投影到**镜像相机**的裁剪空间：

```hlsl
float4 rclip = mul(_WorldToReflClip, float4(worldPos, 1.0));
float inFront = step(1e-4, rclip.w);          // w<=0 = 在镜像相机背后
float2 ruv = rclip.xy / max(abs(rclip.w), 1e-4) * 0.5 + 0.5;
ruv += reflDir.xz * distort;                  // 用反射方向的 xz 做波纹扭曲
float3 planar = SAMPLE_TEXTURE2D(_PlanarRef, sampler_PlanarRef, ruv).rgb;
```

C# 侧每帧写这个矩阵（2022.3 的 `Camera` **没有** `gpuProjectionMatrix`，要自己过 `GL`）：

```csharp
Matrix4x4 gpuProj = GL.GetGPUProjectionMatrix(_cam.projectionMatrix, true); // true = 渲到 RT
mat.SetMatrix(_WorldToReflClip, gpuProj * _cam.worldToCameraMatrix);
```

最后用菲涅尔把它和水体混合。**注意是"替换"不是"累加"**：

```hlsl
float3 reflection = lerp(skyCol, planarCol, saturate(_PlanarStrength));
float reflW = saturate(fres * _SkyReflect);
col = lerp(col, reflection, reflW);          // ← lerp，不是 +=

// 太阳反光带单独累加
col += _SunColor.rgb * pow(saturate(dot(reflDir, mainLight.direction)), _SunGloss)
     * _SunStrength * saturate(0.25 + reflW);
```

> ⚠ 写成 `col += reflection * fres` 的话，**掠射区会被反射洗白** —— 累加只能变亮，而掠射时镜子里映的往往是比水色**更暗**的山坡、树影。于是"反射最强"的地方恰好错得最厉害，方向整个反了（《05》D-13）。
> 判据很简单：**这一项会盖掉下面的东西吗？** 会（反射、折射、泡沫、高光）就用 `lerp`；只是额外加进来的光（自发光、碎闪）才用 `+=`。
> 而碎闪之所以要从 `skyCol` 里拆出来单独累加，是因为它一旦留在 `skyCol` 内，就会在 `planarCol` 接管时被上面那条 lerp 一起抹掉 —— 于是"反射越好，碎闪越没了"。

### 10.5 ★ 倒影出不出来，是**几何**问题不是调参问题

这是做这一潭水时最贵的一课。当时倒影只占潭面一条窄带，我连着调了 `_PlanarStrength`、`_SkyReflect`、`_FresnelPow` 好几轮，**全都没用**。

真相是：水面某个像素能倒出什么，完全由"该像素的反射方向指向哪"决定 ——

| 条件 | 结果 |
| ---- | ---- |
| 相机在 y=3.6、俯角 12° | 潭面反射的是**抬头方向的空天**，只有贴远岸的一条带能接到树 |
| 相机降到 y=1.9、俯角 7° | 掠射角一路覆盖到潭心，倒影面积成倍增加 |
| 树在岸外 3.6~9.1m（离相机 20~26m） | 只张约 8° 仰角 → 只能倒进窄带 |
| 树收到岸外 1.6~4.8m | 仰角张角翻倍 → 大半潭面都能映到树 |

**先算几何，再调权重。**

而"算几何"的手段**不是**在水面上开调试通道 —— 是把**镜像相机自己的 RT 原样导出来看**：

```csharp
var rt = mirrorCam.targetTexture;
var prev = RenderTexture.active;  RenderTexture.active = rt;
var tex = new Texture2D(rt.width, rt.height, TextureFormat.RGBAHalf, false);
tex.ReadPixels(new Rect(0, 0, rt.width, rt.height), 0, 0);  tex.Apply();
RenderTexture.active = prev;
System.IO.File.WriteAllBytes("Docs/screenshots/_pond_rt.png", tex.EncodeToPNG());
```

（本项目做成 **菜单67**。）

> ⚠ `_DebugMode=1`（片元直接 `return planar`）**不够**：那张图仍然要过主相机的 ACES，而且**采样坐标本身就是错的**时它照样"看着有个形状"。本项目就是在这里被带偏的 —— 把池底底盘的椭圆轮廓误读成了岸线，接着在合成端试了至少四种参数组合。
> 一次导出 RT 直接定位了三个 bug：镜像相机绕视轴滚 180°（D-14）、裁剪平面被取反成保留水面以下（D-15）、以及"反射内容一直是深色的，所以累加必然洗白"（D-13）。

规律：**观测通道必须比被观测量更接近源头。** 平面反射的"源头"就是那张 RT；水面上的任何调试输出都已经在它下游了。

### 10.6 ★ 距离淡出会正好抹掉主体

`_ReflFade`（远处退回天空的距离）我一开始给了 45m —— 一个在开阔地形很合理的值。但树就在 24m 外，**淡出曲线恰好在主体位置削掉一半**。改成 120 之后倒影立刻实了。

**教训**：任何"按距离衰减"的参数，都要对着**你这个场景的实际尺度**检查一遍。经验值换个尺度就是自毁。

**你会看到**：对岸的树和绿坡倒进潭面，波纹把倒影揉碎 —— 到这一步，它才终于像"一潭水"而不是"一块水纹材质"。

## 附 B：调试用的三种"仪表"

**别靠眼睛猜，做三个调试输出。** 本项目就靠这个定位了无数次：

```hlsl
// _DepthDebug 1：R=gap  G=depthMix  B=fres
if (_DepthDebug > 0.5)
    return half4(saturate(gap * 0.25), saturate(depthMix), saturate(fres), 1.0);

// _DepthDebug 2：R=原始深度  G=场景视深  B=水面视深   ← 验证深度通道本身通不通
if (_DepthDebug > 1.5)
    return half4(saturate(SampleSceneDepth(screenUV)), saturate(sceneDepth*0.04),
                 saturate(waterDepth*0.04), 1.0);

// _DepthDebug 3：R=screenUV.x  B=screenUV.y  G=深度   ← 验证 UV 算对了没有
// 正常应该是从左到右的红渐变 + 从下到上的蓝渐变
if (_DepthDebug > 2.5)
    return half4(saturate(screenUV.x), saturate(screenUV.y),
                 saturate(SampleSceneDepth(screenUV)), 1.0);
```

### 读法

| 现象 | 结论 |
| ---- | ---- |
| 模式 3 里红/蓝渐变**不铺满画面** | `screenUV` 算错了 → 十有八九是蹭了 `SV_Position` |
| 模式 1 **全蓝**（fres=1） | 法线接近水平，或 `_FresnelPow` 太小 |
| 模式 1 **全绿**（depthMix=1） | `_Absorb` 太大，全池被判成深水 |
| 模式 1 **全黑红**（gap=0） | 深度纹理没开，或 UV 取到无效区域 |

## 附 C：学习路径建议

按这个顺序，每级都**先跑起来看效果再往下**，不要一次写完整份：

1. 第 0–1 级 → 一块会动的青绿色平板（**先只做几何，别管颜色**）
2. 第 2 级 → 有深浅（**这一步最容易踩 `SV_Position` 坑，务必用调试模式验证**）
3. 第 3–4 级 → 透明 + 反射（**水面"活"过来的临界点在这里**）
4. 第 5–6 级 → 高光 + 质感
5. 第 7 级 → 泡沫
6. 第 8 级 → 细分（性能项，最后加）
7. 第 9 级 → 调"好看"
8. 第 10 级 → 平面反射（**视觉收益最大的一级**，值得单独花一天）

> 第 9 级花的时间会比你想像中长得多，而且**它不在 shader 里**。本项目在技术上全部正确之后，仍然因为曝光/环境光/太阳角度问题，画面比参考暗了约 8 倍（线性），并且卡了很久才定位到是"两个菜单各写了一遍太阳仰角"。
