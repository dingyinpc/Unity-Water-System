## 4 补齐实施

### 4.1 设计（唯一旋钮）

`DayNightCycle` 用 **一个 0~1 的 `timeOfDay`** 同时驱动：

| 输出 | 规则 |
| --- | --- |
| 太阳角度 | `elev = sin((t−0.25)·2π) · 75°`（日出 0° / 正午 +75° / 午夜 −75°），方位沿用调好的 236° |
| 太阳强度 | `SmoothStep(elev/18°) · 2.9` |
| 月亮 | 方向 = 太阳反相（方位 +180°），强度 = `SmoothStep(−elev/18°) · 0.30` |
| 天空顶/地平/地面 | 5 条**颜色曲线**按 t 采样（地平做地面半色） |
| 云色 / 云底阴影 | **按"日照因子" `day=saturate((elev+6)/26)` 在"夜色↔白"之间过渡** |
| 日晕强度 | `1−|elev|/45°` 归一（太阳越低晕越大） |
| 雾色 | = 地平色（地平线不留硬边的唯一条件） |
| 水色 | `_SkyZenith/_SkyHorizon/_DeepColor/_ShallowColor/_SunColor` 全部随曲线 |
| 环境光 | 保持 Skybox 模式 + **`DynamicGI.UpdateEnvironment()`（节流）**，天光自然跟着天空变色 |

**关键取舍**：
- 天空 shader 用 `GetMainLight()` 取太阳方向（`Sky_Coast` 自带约定）⇒ **不再同步第二份太阳角**（避开《05》C-4）。
- 不再维护"环境光曲线"——让 Skybox 环境光跟着天空走，少一套互相打架的旋钮。

## 5 验收判据与结果（真机）

### 5.1 四个时段实测（冻结时间后截图，896×379）

| 时段 | 天空带 RGB | 水面带 RGB | 观感 |
| --- | --- | --- | --- |
| 正午 0.50 | (178, 203, 239) | (159, 181, 207) | 淡蓝白晴空 ✅ |
| 日出 0.28 | (212, 169, 174) | (186, 120, 114) | 暖粉晨光 ✅ |
| 黄昏 0.73 | (199, 126, 123) | (203, 97, 78) | **橙红云海 + 水面橙红反光带** ✅ |
| 午夜 0.00 | (5, 9, 20) | (11, 16, 36) | **深蓝夜色** ✅ |

- 四条时段互不相同且单调合理（昼夜→暖→暗），与参考 f3050/f3200/f3400 的**色相走向一致**。
- 回读探针（菜单 111）证明材质值真的写进去了：`天空 顶(0.240,0.120,0.360) 地平(0.950,0.420,0.320) 云(0.703,0.575,0.551) | 太阳 强度1.55 仰角9.4 | 月亮 强度0.00`。

### 5.2 人话版小结

- **做了什么**：给整个场景装了一个"时间旋钮"。转到早上，太阳升起、天空发白发蓝；转到黄昏，天空变橙红、水面跟着变红；转到半夜，天全黑蓝、太阳换成月光。
- **怎么知道做对了**：把时间**冻住**（不然波浪在动，截图对不上），分别转到四个时间点各截一张，量天空和水面的颜色——四个时间点的颜色完全不同、而且符合直觉。
- **顺带修了一个**：天气系统一开始"永远是白天"（天空全白），真因见 §5.3。

### 5.3 本轮踩的坑（值得单记）

**Unity 的 `Gradient` 字段在 MonoBehaviour 上会被还原成默认值**：本机实测，代码里刚赋好 9 个关键帧的 `Gradient`，
下一句读回 `colorKeys.Length == 2`、`Evaluate()` 恒为**白色** —— 表现为"天空永远是白的、昼夜没反应"。
排查过程绕了弯路（先怀疑材质为空、再怀疑云色公式），最后靠**回读探针**（把曲线自身的 key 数与求值结果写进日志）定性。
**改法**：颜色曲线改用**朴素 `Color[] + float[]` 数组 + 手写线性插值**（可序列化、行为可预测），不再用 `Gradient`。

**另一条**：云色最初写成 `lerp(地平色, 白, 0.75)`，夜里也几乎全白（整片天空发白）。
必须引入**日照因子** `day = saturate((elev+6)/26)` 做过渡。

## 8 补齐（2026-10-20）：月面圆盘 + 星空银河（参考 S12）

> 触发：R03 §6 遗留第 1、2 条（无月面 / 无星空）。参考 f3400 的夜空是"深蓝 + 月盘 + 云影"，
> 我们之前只有"深蓝 + 云"，夜戏说服力差一半。

### 8.1 做法

| 部件 | 实现 | 关键量 |
| --- | --- | --- |
| 星星 | 视线折成**经纬网格**，每格按 hash 决定是否有星、位置/星等/闪烁 | `_StarGrid=320`、阈值 `h>0.966`、`_StarBright=1.6` |
| 银河 | 一条斜带 `exp(-(d·n)²·16)` × 低频噪声 | `_GalaxyAmount=0.30` |
| 月面 | 圆盘 `smoothstep(cosR, cosR+ε, dot(d, moonDir))` + **相位终止线** + 月海噪声 + 晕 | `_MoonSize=0.03rad(≈1.7°)`、`_MoonPhase=0.62` |
| 驱动 | `DayNightCycle.Apply()` 写 `_NightAmount/_MoonAmount/_MoonDir/_MoonPhase/_MoonSize/_MoonColor` | 白天全为 0 |

**为什么星星不用 3D 体素**：球面与立方体格相交的形状随机，星点大小/密度会随方向忽大忽小；
经纬网格的代价只是两极/经度接缝略密，夜空里看不出来。

### 8.2 本轮三个真 bug（都表现为"代码在跑，但月亮看不见"）

1. **月亮被放到了背后**：方向光的方位约定是 `Euler(y=a)` ⇒ **光源在天空方位 a+180°**。
   第一版写 `y = sunAzimuth + 180`，光源落到 236°，而相机朝 58° → 月亮在身后。
   改成 `y = sunAzimuth`（与太阳同方位、仰角相反）。
2. **月亮在正上方出画**：严格镜像 ⇒ 午夜仰角 +75°，而相机俯仰 +4.5°、垂直 FOV 52°
   （上边缘约 30°）→ 拍不到。加 `moonElevationScale = 0.30`（美术化处理，午夜≈+22°低垂入画）。
3. **月相公式把满月算成暗盘**：`term = cos(phase·2π)` 在 phase=0.62 时给出 -0.727，
   再配 `smoothstep(term+0.06, term-0.06, x)` ⇒ 只有边缘一条亮，整盘近乎全黑。
   正确关系：受照比例 `k = 1-|2p-1|`、终止线 `x = 1-2k`、亮面在 +x。
4. **月盘被云整片盖住**：月面原先画在云之前，`cloudCover=0.68` 时云把月盘整个覆盖。
   改到云**之后**绘制，并按 `1 - cloud*0.55` 透光（云后透光的月亮）。

> 排查方法：新增 `Tools/Ocean/116 夜空诊断(写探针)`，直接打印
> `night / moonAmt / moonDir / camFwd / dot / moonLightRot`。
> 实测 `dot=0.950`（=18°离画面中心）证明"确实在画面里"，才把怀疑范围收敛到相位与云。

### 8.3 实测（冻结）

| 项 | 午夜 | 正午 |
| --- | --- | --- |
| 天空带 RGB 均值 | (6.7, 10.2, 22.4) | (185, 207, 239) |
| 天空最亮像素 | **205**（月盘） | 243（太阳方向） |
| 月盘亮像素（luma>140） | **403 px，中心 (440, 64)** | 0 |

- 星星在画面上半部可见（细点），云穿过月亮时月盘被压暗但不消失。
- **正午零回归**：星星/月亮全部乘 `_NightAmount`，白天该分支整段跳过 ⇒ 数学上逐位不变。
  （跨会话对比正午图有 0.06% 差异，那是云用 `_Time.y` 的相位不同，不是本改动。）

### 8.4 人话版

- 以前夜里只有"深蓝天空 + 云"，现在**有月亮、有星星、还有一条淡淡的银河**。
- 月亮不是一张贴图，是用数学"画"出来的：一个圆盘，按相位切掉一部分（所以有圆缺），
  表面加一点斑驳（月海），外面一圈光晕。云飘过时会遮住它一部分。
- 中间踩了四个坑，全都是"代码看着对、月亮就是不见"：方向反了、仰角高到出画、
  月相算反了、被云整片盖住。最后靠一个**只打印参数的诊断菜单**定位，而不是继续猜。
