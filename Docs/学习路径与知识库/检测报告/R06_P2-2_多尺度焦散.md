## 2 我方现状（实施前）

- `Water_Pool` 只有**单层**程序化焦散：两个正弦网格取峰 `pow(1-|c1*c2|,3)`，**纯加法**打在池底上，波场梯度调制。
- 缺点：单一尺度（近看一条密度）、有周期性平铺感、无 RGB 色散、且加法项在被照亮的白色池底上**被削平**。

---

## 3 差距对比

| 项 | 参考 | 我方（前） |
| --- | --- | --- |
| 尺度 | 小/中/大三档 + 水深平滑混合 | 单层 |

| 合成方式 | 与水体/池底混合 | 纯加法（亮底上被削平） |

## 4 补齐实施

### 4.1 方案

`Water_Pool.shader` 新增三个函数：

| 函数 | 作用 |
| --- | --- |
| `CausticPat` | 单层图案（两正弦网格取峰） |
| `CausticDeTile` | **三角随机平移 + 重心权重混合**（C12 去平铺）：按 simplex 布局划三角格，三顶点各取固定随机偏移采样，`max(0.5-r²,0)` 作权重归一 |
| `CausticRGB` | **RGB 色散**（C13）：三通道用略微不同的尺度/偏移采样 |

合成（frag）：
- **三层**：细网 `×2.2` / 中 `×1.0` / 大斑 `×0.45`，权重由 `_CausticDepthMix` 经 smoothstep 给出（C12 水深连续混合）。
- **去平铺强度按层递减**（细网 1.0 / 中 0.35 / 大斑 0.0）——见 §4.3 翻车。
- **乘性打在池底**：`bottomLit = bottom * (1 + caustic·_CausticsStrength·1.3·gradMod)`；再补 0.22 的散射亮。
- 属性：`_CausticMode(0关/1单层旧/2多尺度)`、`_CausticDepthMix`、`_CausticDisperse`、`_CausticDetile`。
- 菜单 `160 关 / 161 单层(旧) / 162 多尺度 / 163 细网定稿 / 164 大斑档`。

### 4.2 编译前提

无新 include / 关键字，改动全在 `Water_Pool.shader` 内。

### 4.3 三次"翻车"（值得单记）

1. **纯加法焦散在亮池底上被削平**：首版沿用旧加法 → A/B 最大通道差仅 23，肉眼几乎看不出网。改**乘性调制池底色**后 max 差升到 60。
2. **三角偏移用在大斑层 → 水面出现大块 facet**：低频层每个三角格尺寸大，格边不同随机偏移在画面上就是"块状拼接"。改：**只让高频细网层去平铺**（格小、接缝近乎像素级）。
3. **A/B 菜单 163 漏置 `_CausticMode`**：只改了参数、模式停在上一次的"单层" → 161→163 两张截图**逐字节相同**（差点误判"多尺度没效果"）。改：163/164 显式写 `_CausticMode=2`。
   > 同《05》：**A/B 工具必须把"被改变的观测状态"一并写全**。

**另一条方法学**：焦散是**动画**，A/B 必须**同一冻结会话**内连续截（不同会话 `_Time.y` 冻结在不同相位 → 会凭空多出 60%+ 的差异）。

### 5.1 人话版小结

- **做了什么**：泳池底下的"光网"——以前只有一层、密度单一、还会看出重复的花纹。现在改成**三层叠加**（细网+中+大斑），并用**三角形随机错位**把重复纹打散，R/G/B 三个颜色通道还各走一点点不同的变形（形成水底微微的彩虹边）。
- **一个关键小改动**：以前是"往画面加亮"——可是池底本来就是白的，加了看不出来。改成**"把池底本身调亮调暗"**（乘上去），光网才读得出来。
- **怎么证明有效**：冻结后关/开各截一张，**18.6% 的像素**发生了变化，差异图里能看到一张**连续的网**（不是噪点）。
- **踩的坑**：三角错位用在大斑那层时，画面上冒出一块块"拼贴方块"；改成只让细网层错位就好了。另外测试菜单一度忘了把"模式"一起切，导致两张图一模一样，白惊一场。

## 6 遗留与风险

1. ⚠ **不是严格的"三顶点随机偏移 + 重心插值"**：实现是同一族做法（三角格 + 重心权重 + 三顶点采样），但为消除低频接缝把去平铺限制在高频层，与参考的"全尺度去平铺"有差异。
2. ⚠ **色散是"三通道略微错位/错尺度"的近似**，参考用的是"网格形变前后**面积比**"算聚光强度后写 RGB；但主观"彩虹边"目标一致。
3. ⚠ **水深分层用的是 `_CausticDepthMix` 旋钮**而非真实水底深度（泳池底是平的，没有深度场可用）。若有斜底/深浅池，应改由场景深度驱动。
4. ⚠ **性能未测**：三层 × 三通道 × 3 顶点采样 = 27 次图案求值/像素（池水占屏约 1/3）。
5. ⚠ 未接 Main/Pond/Ocean：路线目标就是 Pool；如需在别的场景用，同一套函数可复制。
6. ⚠ 焦散是**动画**：所有 A/B 必须**同会话冻结**（见 §4.3）。
