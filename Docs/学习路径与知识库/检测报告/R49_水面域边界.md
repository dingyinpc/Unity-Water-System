# R49 水面域边界"黑楔" —— 三个假设，两个证伪，一个悬案

> 2026-11-01。这是 R46 就发现、连续三轮没修的缺陷。本轮**没有修好**，但把范围缩到了很小，
> 并留下两条"别再试"的结论。

## 0 结论先行

| # | 假设 | 验证 | 结论 |
| --- | --- | --- | --- |
| H1 | 域外 clamp 到 rim(-8m) ⇒ 深浅硬跳变，加渐变即可 | 渐变 120m：全画面 45.5% 变化，但**整片泻湖被压深**（暗水 26%→85%，亮度 125→50）；收到 35m：仅 1.73% 变化，**肉眼无感** | ⚠ **可用但不对症** |

## 1 已确认的事实

1. **它不是黑色**：楔内 RGB `(73,149,132)`，同一画面浅水 `(112,200,180)`、远海 `(54,117,102)`。
   所谓"黑楔"其实是**一块偏暗的青绿 + 一条硬直边**。
2. **边界是直线**：435~451 列梯度剖面是**宽缓峰**（不是 1px 尖线），位置随相机旋转 —— 说明它是
   世界空间里的一条**矩形边**，不是屏幕空间伪影。
3. **足印矩形是 `_IsletFloorHRect = (-256, -120, 512, -8)`**（全局变量，脚本写）：
   X ∈ [-256, 256]、**Z ∈ [-120, 392]** —— 注意 Z 的起点是 **-120**，而不是地形的 -256。
   相机朝 -Z 看，所以 **Z=-120 这条边就落在画面里**。
4. **水深来自 `_IsletFloorH` 烘焙高度场**（`_DepthSource = 1`），足印外用 clamp。

## 2 改了什么（保留，但是"守卫"不是"解药"）

`Water_Lagoon.shader` 新增：

```
_DomainFade ("域外过渡宽度(米)", Float) = 35
_DeepDepth  ("域外深水深度(米)", Float) = 14
```

在 `vd` 算完后，对**足印边界内侧** `_DomainFade` 米做 `lerp(vd, max(vd,_DeepDepth), tIn)`，
把"浅→深"的一步台阶摊成一段坡。

- `_DomainFade = 120`：效果过猛（整片泻湖变深），**不要用**；
- `_DomainFade = 35`：几乎无感（1.73% 像素）；
- 默认保持 35。

菜单：`R49/90`（关=硬边，A/B 用）/ `90b`（开 35m）/ `93` 探针 / `94` 水深可视化 / `96` 隐藏水面。

## 3 为什么没修好（诚实的归因）

硬边两侧**都是深水**（域内靠边是 rim，域外是 clamp 后的同一个 rim），所以"加深"不能消除接缝；
真正要改的是**足印边界的位置**或**边界外侧的深度来源**：

- 方案 A：把 `_IsletFloorHRect` 的 Z 起点从 **-120 扩到 -256**（覆盖整个地形），让边界移出画面；
- 方案 B：足印外不再 clamp，而是**沿边缘高度继续外推**（乘一个平缓的坡度）；
- 方案 C：把这条矩形边做成**不规则岸线**（噪声扰动），让它不像一条直尺。

A 最省事、最可能一次成功：`IsletFloorHBinder` 里烘焙矩形是按某次 R16 的采样范围定的，不是地形全幅。

## 4 采集可信度问题（本轮新发现，值得记档）

「关闭水面渲染器」后截图与开水面**逐位相同（最大差 0）**，但同一会话里 `_DomainFade=120` 能让 45% 像素变化
⇒ 两条证据自相矛盾。唯一自洽的解释是**那次截图没真正重拍**（拿了旧文件）。

> **以后做"关掉某个对象看还在不在"的二分，必须同时打印：截图文件的修改时间 + 与上一张的哈希差。**
> 只比图不看时间，会把"采集失败"当成"结论"。

## 7 R50 追加：两件事被证实、一件被证伪

### 7.1 地形确实"到此为止"（不是 bug）

`IsletTerrain.Origin = (-256, y, **-120**)`，`SizeXZ = 512` ⇒ 地形铺在 X∈[-256,256]、**Z∈[-120,392]**。
`IsletFloorHBinder.rect` 就是按这个 Origin 写的，**烘焙与采样是一致的**。
所以那条边 = **解析地面函数的定义域边界**，不是接错了参数。

### 7.2 暗区不是"透过水看到的海底"

决定性实验：把水改成**全不透明**（`_Opacity=1`）。

| | 全画面变化 | 左上区最大列梯度 |
| --- | --- | --- |
| 半透明 → 全不透明 | **50.6% 像素变化** | 4.41 → 4.95 |

⇒ 变不透明后暗区**依然存在**（甚至在边缘更硬），**不是海底/地形透出来的**，是**水面自己算出来的颜色**。

### 7.3 我的测量指标本身有缺陷（重要）

回头看：`左上区最大列梯度` 的峰值一直落在**第 49 列**——那是**画面左边缘**（暗角/边框），
不是我们要测的那条斜边。所以前面几轮"最大梯度 4.49→4.45"之类的比较，**测的根本不是同一条边**。

> 教训：测"某条边有没有变软"，必须先**定位这条边**（Hough 直线 / 手画 ROI），
> 不能用"整块区域的最大梯度"当代理——它会被更亮的其它边缘抢走。

## 9 下一轮的正确打法（已经排除掉三条错路）

1. **先做正确的量具**：在楔区用 `HoughLinesP` 找出那条边的实际位置与角度，再沿法线取剖面测"台阶高度"；
2. **对症的修法**：不要用 `max(vd, deep)`（会把整片泻湖压深），而是**沿边界的法线方向做 1D 剖面**：
   在边界前后各 40m 内，把 vd 从"边缘实际值"线性过渡到"深水值"，**只在剖面带内改**；
3. 或者干脆**扩张地形定义域**（Origin.z 从 -120 改到 -256、SizeXZ 改 768）并重烘 —— 世界变大，边自然移出画面（代价：地形重建 + 全部图层重刷）。

## 10 人话版（含 R50 的更新）
- 这块"黑楔"其实不黑，是**偏暗的青色**，问题是它和旁边的亮水之间有条**笔直的边**。
- 我先怀疑"深水跳变"，加渐变：拉 120 米——整片泻湖跟着变暗（过头）；收 35 米——看不出来。
- 用 shader 自带的水深可视化一看：**两边本来都已经是"深水满格"**，所以加深没有意义。
- 想判断是不是海底透出来的，就把水调成**全不透明**——暗区**还在**。所以是**水自己算出来的**，不是海底。
- 查了代码：岛的地形**本来就只铺到 Z=-120**（不是接错参数），所以那条边是"世界到此为止"的边界。
- 我还发现**自己的量具测错了地方**：一直报"最大梯度在第 49 列"，那是画面左边缘，不是那条斜边。所以前几轮的 "4.49→4.45" 结论都不作数。
- 下一轮先用直线检测把那条边找出来，再沿它的法线量"台阶有多高"，然后**只在那条窄带里**做过渡——不要再用"整片加深"这种猛药。

## 11 R51：把量具做对了，把四种原因排掉了

### 11.1 新量具（这才是应该一开始就有的）

`Tools/R51/r51_edge_probe.py`：
Canny → `HoughLinesP` 找直线 → 沿**法线**取亮度剖面 → 报 `step`（两侧平台差）、`width`（10%→90% 跨度）、
`ratio = step/width`（同样的高度，跨得越窄越硬）。

**实测基线（R51_A）**：`line=(36,88)-(238,23)`，`step=121`，`width=66`，`ratio=1.83~1.95`。
即：**120 个灰阶的台阶，跨 60 像素** —— 这就是肉眼看到的"硬边"的准确描述。

### 11.2 有效二分（这次带哈希，不是旧图）

| 实验 | 台阶比 | 结论 |
| --- | --- | --- |
| 水面开 | **2.02** | — |
| 水面关（哈希不同，确认为新帧） | **0.43** | ✅ **边就是水面画的** |
| 关平行光阴影 | 1.94 → **1.94**（逐位相同） | ❌ 不是阴影 |
| 水调全不透明 | 边仍在 | ❌ 不是海底透出 |

### 11.3 三种"域边界过渡"全部失败（已回滚）

| 方案 | 台阶比 | 副作用 |
| --- | --- | --- |
| 内侧渐变 120m | — | 整片泻湖压深（暗水 26%→85%） |
| 内侧渐变 35m | — | 仅 1.73% 像素，无感 |
| 跨边界对称 60m | **1.83 → 3.11（更硬）** | — |

**共同原因**：两侧的 `vd` 都已经是"深度饱和"（depthMix≈1），在 `vd` 上做任何文章都改不动颜色。
⇒ **`vd` 不是正确的杠杆**，已回滚到原始实现（回滚后 ratio 1.95，与基线一致，未留回归）。

### 11.4 现在最可信的下一步

颜色差既然不来自 `vd`，就只剩水面着色里**与深度无关的那些项**在边界两侧不一致
（`sandMix` 的沙底返色、`_BottomBlend`、以及域内域外 `floorY` 取值不同导致的反射/散射差）。

正确做法：**在"最终颜色"上做域边界混色**，而不是在深度上：

```hlsl
// 伪代码：先算出 col，再按到边界的距离混一份"域外参考色"
float m = 1.0 - smoothstep(0.0, _DomainFade, abs(dOut));
col = lerp(col, colDeepPreset, m * 0.85);
```

这样无论颜色差来自哪一项，都会被同一个 mask 摊平；而且 mask 宽度可以直接用量具标定
（目标：`ratio < 0.8`）。

### 11.5 教训（写进流程）

1. **测一条边，必须先定位这条边**（Hough/ROI），不能用"整块区域最大梯度"——它会被暗角抢走；
2. **"关掉某对象看还在不在"必须打印截图 mtime + 哈希**，否则会把"采集没刷新"当成"结论"（R49 就栽过）；
3. **先量再改**：这次先拿到 `step=121 / width=66`，才看清"在 vd 上加深"根本不可能改变 60 像素宽的台阶。
