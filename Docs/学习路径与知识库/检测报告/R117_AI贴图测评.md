# AI 生图贴图测评：Nano Banana 2（经 Google Flow）

> 目的：回答"用生图模型做这套工程的贴图，到底行不行"。
> 方法：**不是看几张图，而是量数字 + 真的装进场景跑**。
> 日期：2026-11-04

---

## 一、结论（先说结果）

| 项目 | 行不行 | 证据 |
| --- | --- | --- |
| **无缝平铺**（岩石/沙子这种图案贴图） | ✅ **第一张就成** | 接缝比 **1.13 / 0.75**（1.0=完全连续，>2 才能看出缝）；2×2 拼接**肉眼无接缝** |
| **单株植被带白底**（棕榈叶） | ✅ **质量很高** | 纯白底 68.7%，主体 31.3%，主体只有一个连通块（不碎） |
| **直接出法线图** | ❌ 不建议 | 别让它生成 normal，**从高度图自己算**更可靠 |
| **出图后直接当贴图用** | ⚠️ 要后处理 | 分辨率固定 1024²、是 JPG（有压缩）、比例只能选 1:1；需要自己做 alpha、法线、色彩空间 |

**一句话：这类贴图（岩石/沙/树皮/植被卡）可以让 AI 出，而且质量够用；但它只适合做 albedo，法线和 alpha 要我们自己补。**

## 三、端到端验证：真的装进场景

把沙贴图接进 Ocean 的沙滩（世界空间采样，**不需要 UV**）：

```
// Beach_Sand.shader
float3 tex = SAMPLE_TEXTURE2D(_SandTex, sampler_SandTex, IN.worldPos.xz * _SandTexScale).rgb;
float tl = dot(tex, float3(0.299, 0.587, 0.114));
base *= 1.0 + (tl - 0.62) * 1.30 * _SandTexAmount;   // 保持均值，只加结构
```

| | 亮度 | 对比 | 饱和 | 观感 |
| --- | --- | --- | --- | --- |
| 纯程序化 | 137.8 | 39.6 | 123.9 | 一片均匀的黄 |
| **贴 AI 沙贴图** | **142.7** | 40.8 | 120.2 | **有风的沙纹起伏** |

关键技术点：**用亮度而不是用它的颜色**。否则贴图色相会把整幅画面的色调带跑（第一次试的时候
直接乘颜色，整片沙变亮变黄，改回"保均值 + 只取明度结构"才对）。

菜单：`Tools/R117/90` 装、`90b` 拆（可逆）。

## 四、踩到/学到的

1. **提示词里加 "no objects / no people" 容易触发策略拦截** —— 用朴素描述（"close up photograph of …"）更稳。
2. **它出的图是 1024² JPG**：做 2K 地面贴图会糊，需要的话可以出 4 张拼或者后期超分。
3. **法线不要让它生成**：从 albedo 的亮度反推高度图 → Sobel 求法线，是可控且可复现的做法（Python 十行）。
4. **平铺的"重复感"**靠单一贴图解决不了：要用**两层不同尺度/旋转**叠加（这就是我们程序化噪声一直在做的事）。

## 六、自动化流水线（R118）

上面那些"人工步骤"已经全部脚本化，现在**你只管把图丢进 `Assets/Art/Textures/AI/Raw/`**。

### 一条命令 / 一个菜单

```
Tools/R118/90 AI贴图 处理+导入(一条龙)
```

它依次做四件事：

| 步骤 | 内容 |
| --- | --- |
| ① 后处理 | 调 `Tools/TexAI/texai.py`：**自动判定**是"图案贴图"还是"白底植被卡" |
| ② 无缝 | 量接缝比；**>1.6 才修**（错位混合），≤1.6 原样通过（不乱动细节） |
| ③ 法线 | 从亮度反推高度 → Sobel → 切线空间法线图（不让 AI 生成 normal） |
| ④ 导入设置 | 法线图设 `NormalMap` 且关 sRGB；RGBA 卡设 `Clamp + alphaIsTransparency`；其余 `Repeat + aniso8 + trilinear` |

### 自动判定规则
- 画面里"接近纯白"的像素 > **45%** ⇒ 当**植被卡**：抠 alpha、去白边、裁到内容外接框 + 2% 安全边
- 否则 ⇒ 当**图案贴图**：查/修无缝 + 出法线

### 三条实测产物（来自本次 3 张样图）

| 输入 | 判定 | 产出 | 关键数字 |
| --- | --- | --- | --- |
| `Rock_Basalt_AI.jpg` | tile | albedo + normal | 接缝 1.29/1.13，原样通过 |
| `Sand_Fine_AI.jpg` | tile | albedo + normal | 接缝 1.13/0.75，原样通过 |
| `Palm_Frond_AI.jpg` | card | RGBA（929×829） | 白底 69.7%、主体 30.3%、边缘干净 |

### 端到端接线

| 贴图 | 接到哪里 | 怎么处理"没有 UV" |
| --- | --- | --- |
| 沙 | `Beach_Sand`（世界 XZ 采样） | 世界坐标直接当 UV，天然平铺 |
| 岩石 | `IsletRockSplat`（**三平面投影**） | 按法线权重混合 XZ/YZ/XY 三个方向 |

### ⚠ 一个必须记住的坑（实测 0.000% 像素差换来的）

岩石贴图第一版乘在 `rock` 上，**画面像素差 0.000%** —— 完全没生效。
原因：后面有一行 `albedo = lerp(rock, _MossColor, mossW)`，
而程序化岩石网格的**顶点色 R=1 ⇒ mossW≈1 ⇒ albedo 基本就是苔色**，
把前面乘的贴图整个覆盖掉了。

**教训**：给"多层混合"的材质加贴图，要乘在**最终颜色的那一层**（albedo 之后），
不是你以为的中间变量上。判据就是同会话像素差 —— 0.000% 就是没生效。

### 诚实结论：岩石贴图在这个距离上**几乎看不出来**

修好之后像素差 0.202%（确实生效），但视觉上仍然是一块块平面。
原因不是接口错，是**频率失配**：1024² 贴在 0.45 米见方上 ⇒ 20 米外一个像素要盖住几十个纹素
⇒ mip 一平均就回到一片平灰。

于是：
- **小礁石（2~3 米、20 米开外）**：贴图帮助很小，几何分面才是主导；
- **要看出贴图，得给"大物体"用**（崖体/远景山），或者把贴图做大尺度特征（20~50cm 的裂纹/层理）。

## 七、大物体才看得见（R119）

R118 的结论是"小礁石看不出贴图"。这一轮验证反面：**给几百米大的远景山体贴**。

- 材质：`Ocean_FarLand`（`DistantLand` shader，高度渐变 + 雾）
- 加三平面采样，**尺度 0.004（250 米/周期）**
- 第一版直接采样 → 画面变成"一层白霜"（高频麻点在 1.4 米/像素的距离上全炸开）
- 改成 **`SAMPLE_TEXTURE2D_LOD(..., 5)` 强制采粗 mip**（约 32×32）⇒ 只剩低频层理，白霜消失

**结论成立**：同一张贴图，
- 2~3 米的小礁石（20 米外）→ 看不出；
- 500 米的远景山 → 看得出来（但要**限频**，不然是噪点）。

这就是"贴图要配尺度"的实证：**贴图特征尺寸 ≈ 3~10 个屏幕像素**才读得出来。

## 八、棕榈叶（R120）—— 唯一一处"贴图能立刻看出来"的地方

棕榈是**真实模型**（`SM_Palm_Coconut_01`，77k 顶点、3 个子网格），叶片按**网格 UV** 采样 `_BaseMap`。

### 做法
AI 叶片自带 alpha 轮廓，直接换会把叶片"切碎"（因为网格是分片羽叶，不是一整片）。
所以先做一版**扁平化**：把透明背景填成"叶片平均色"，只保留叶内的颜色/明暗变化。

```
Palm_Frond_AI_rgba.png  →  Palm_Frond_AI_flat.png（背景填平均色 BGR 52/134/118）
```

### A/B（同会话冻结，像素差 **27.2%**）

| | 亮度 | 饱和 | 观感 |
| --- | --- | --- | --- |
| 旧程序化叶脉 | 126.6 | 72.0 | 扁平黄绿，像塑料 |
| AI 叶片（直接用） | 111.7 | 61.8 | 有层次，但整体偏暗 |
| **AI 叶片 + 基色提亮 35%** | **120.5** | **128.2** | **翠绿有层次，叶脉可读** |

### 一个改色的小坑
`Islet_PalmLeaf._BaseColor` 本来是**绿色调** (0.36, 0.60, 0.235)，不是白色。
我第一次为了提亮直接改成 (1.35,1.35,1.25) ⇒ 绿色被冲掉，画面变灰变亮（142.5 / 饱和 116.8）。
正确做法是**按比例**：×1.35 → (0.486, 0.81, 0.317)。

⇒ 凡是"提亮/压暗"一个材质，先看它的基色是不是带色相的，**乘系数而不是覆盖**。

### 机位口径待定
`Style/207` 现在给出的是**棕榈特写**；`207b` 还原是**宽阔泻湖**。
两个机位都合理，但"交付口径"需要拍板。当前验收用的是 207b（宽阔视角），
因为它和参考的数字最接近：**亮度 123.1 vs 参考 123.3、近黑 12.9% vs 11%**。

## ⚠ 方法论问题：机位在两次运行之间会漂移

做这一轮时发现：**同一条 `verify_scenes.ps1`，前后两次给出的 Ocean 构图不一样**
（一次是"沙滩在下、海在中"的平视，另一次是"沿海滩斜看"的低角度）。

原因大概率是：我在编辑模式下多次执行 `Tools/Project/128 保存当前场景(显式)`，
把某次 Play 之后的相机状态**存进了场景**。

影响：
- **同会话内的 A/B 仍然有效**（相机不动，像素差可信）；
- **跨会话的数字基线会跟着构图一起变**，所以基线只能做"量级报警"，不能做"精确回归"。

修法（下一轮）：给每个展示场景固定一个"验收机位"菜单，并在 `verify_scenes.ps1` 里
**先跑机位菜单再采集**，让基线的构图恒定。

## 十、树干树皮（R123）—— 做完了，但**判定不值得**

### 做了什么
生成一张真实棕榈树皮（横向环痕 + 纵向纤维 + 地衣），走完整流水线：

| 项 | 结果 |
| --- | --- |
| 原图接缝 | **1.49 / 2.07**（可见） |
| 自动修复后 | **1.12 / 1.34** |
| 亮度归一化 | 均值 103 → 197（对齐原贴图 228，避免整根树干变黑） |

### 验证：把相机专门挪到能看见树干的位置
同会话 A/B，像素差 **0.17%**。

看图就明白了：**这根树干是纯黑的剪影**（太阳在它背后，背面只有极弱的环境光）。
树皮贴图再清晰，乘在一个接近 0 的亮度上还是 0。

### 结论
**已还原**（`R123/90b`）。

> 贴图能解决的是"**表面细节**"，解决不了"**这个面根本没被光照到**"。
> 在 Islet 这个逆光机位下，树干是构图里的剪影元素 —— 要么改光/改构图（让树干受光），
> 要么就接受它是黑的。花成本做树皮，在这个场景里是**无效投入**。

### 由此得到的选择标准（贴图三问）
1. 这块**在画面里有多大**？（小礁石 vs 远景山）
2. **一个像素盖住多少个纹素**？（差 > 10 倍就等于没贴）
3. **这个面有没有光**？（纯黑面贴什么都没用）

三问都过，才值得生成贴图。

## 十一、R127：AI 云密度贴图 —— **试了四种接法，全部失败**（记档，代码保留可逆）

用户授权"额度管够，只要能更好"。所以拿 AI 去打最后一个结构缺口：**云的形状**。

### 生成
Nano Banana 2，1024²，俯视积云（白团 + 花椰菜边 + 碎絮尾巴），接缝 1.08/**7.21** → 自动修到 **1.11/0.95**。
素材本身质量很好，问题不在素材。

### 四种接法，逐个证伪

| # | 接法 | 结果 |
| --- | --- | --- |
| 1 | 贴图**接管柱覆盖度** `SkyColumnCoverage` | 像素差 **41.6%**（画面确实变了），但云变成**一根根竖条/锥形**；铺开 4/8/16 km 三档同一个病 |
| 2 | 同上 + 强制降 mip（2/3/4） | 竖条没了，但**锥形底座**还在；越柔越糊（天空带亮度 115.9→111.3→104.8） |
| 3 | 贴图只做**表面侵蚀**（轮廓仍程序化） | 像素差 26.7%，轮廓保住了，但蓝天里出现**竖向拉丝** |
| 4 | 全部还原 | 六场景数字与上一轮**完全一致**（零回归） |

### 为什么必然失败（机理）

`SkyDensity` 的公式是

```hlsl
float d = saturate((cover - h) / max(cover, 0.20));
```

`cover` 被当成 **"这一列云有多高"** 来读（它的作用就是造"平底 + 尖顶"）。
所以任何横向的高频信息，到了这里都会变成 **"柱子高矮不一"** ⇒ 屏幕上就是竖条。
这不是参数问题，是**模型语义不匹配**：2D 密度图适合"投影到平面"的云层（薄片/天穹图），
不适合这个"沿射线行进、按高度切片"的体渲染。

### 想真做对，只有两条路

1. **3D 噪声体**（把 AI 的 2D 图按高度错切片堆成 volume，或用 compute 生成 3D 场）——工作量大，但这是正解；
2. **天穹全景图**（AI 生成 equirect 天空，直接当 skybox 用）——立刻出照片级效果，代价是**失去动态云和昼夜渐变**。

## 十二、这轮踩到的三个坑（比结论更值钱）

### 1. `CloudDensity()` 是**死代码**
改了半天没反应，原因是真正生效的是 **`SkyColumnCoverage` + `SkyDensity`**（R108 把 Islet 那套云移植过来时新写的），
旧的 `CloudDensity` 还留在文件里、**没有任何调用点**。
> 教训：改 shader 前先 `grep` 函数名看**有没有调用点**，别按函数名的语义猜。

### 2. `TEXTURE2D/SAMPLER` 写进了 `CBUFFER`
能编译通过、`check_shader` 也报 clean，但 **SRP Batcher 不会上传这些 uniform** ⇒
材质上 `_CloudTexAmt` 明明是 1，shader 里读到的还是 0，画面纹丝不动（实测像素差 0.01%）。
> 规则：纹理和采样器声明**必须在 `CBUFFER_START/END` 之外**。

### 3. 场景切换又一次静默失败
`Tools/Project/126 打开 FFTScene` 之后截图，文件名却是 `still_OceanScene_*`——
**切场景没成功，还在上一个场景里测**。
> 重申 AGENTS 第 23 条：每次切场景后必须 `Tools/Project/125` 确认 `MENU125 当前场景=xxx`。

### 诊断手法（有效，记下来）
想确认"材质到底有没有在渲染"，最便宜的办法是**把它改成纯红**（`R127/94`）：
一变红就说明链路通，问题在参数/分支；不变红就是根本没接上。
