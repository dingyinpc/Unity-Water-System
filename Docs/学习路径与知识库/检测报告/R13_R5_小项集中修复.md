## 2. 本轮实锤（排障记录）

1. **1.33Hz 幻影**：Pool/Pond 的 D4 主频在各自速度参数减半后逐位不动——主频率来源
   是**波动方程固定步进（60Hz×2步/帧）的组合动画**，不是焦散/波速参数。参数级修复
   对此无效 ⇒ #1/#2 升级结构性项（改的是动画混合构成或判据的频段归因）。
2. **相机级后处理开关**（URP 经典坑再现）：FFTScene 的 Volume 写了调色档但截图逐位
   不变——`UniversalAdditionalCameraData.renderPostProcessing` 没开；且 URP14 属性名
   是 `renderPostProcessing` 不是 `postProcessing`（后者编译能过但无效）。
3. **profile 空壳**：`AssetDatabase.LoadAssetAtPath<VolumeProfile>` 对刚建的 .profile
   偶发取空 → 90 重建了空壳 profile 把 190 的覆盖丢掉；592 改为"从场景 Volume 取
   sharedProfile + 缺什么覆盖自建什么"，自足。
4. Main 的 D2 尖峰（7.3/9.0）在 autoDemo 放宽到 12 秒后仍在——排除法继续：源在
   Gerstner 幅值调制的低频突变或交互涟漪爆发，留 R6 前再诊断。

## 4. 结论

R5 的定位是"参数级清账"：**2 项全额销账，4 项明确降级为结构性**（带归因诊断），
2 项部分改善挂起。至此"调参能到的极限"已摸清，剩余差距全部指向三类结构工作：
① 表面动画的构成（波动方程步进 vs 参考的频谱演化）；② 云/水的对比度光照模型；
③ 逐段角色匹配（平移 vs 原地演化）。这些超出"小修"定义，按策划归 R6 总验收的
差距清单处置（是否投入由用户拍板）。
